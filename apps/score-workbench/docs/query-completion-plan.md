# Query 보완 추천 — 기획 및 첫 구현

## 목표와 단계

사용자가 기억한 선율의 작은 누락·음높이·옥타브 차이를 악보 근거로 제안한다. 사용자가 듣고 적용한다.

1. 현재: 반환된 검색 결과의 정렬로 단일 음 추가/반음·온음 변경/한 옥타브 변경 추천. 악보·재생·적용·Undo 및 명시적 JSON 내보내기.
2. 후속: 평가 세트로 추천 적절성·오추천률·추천 후 원곡 순위·속도 측정. 두 음 누락의 후보 위치 문제는 검색 엔진에서 별도 진단.
3. 후속: 동의를 받은 사용자 사례 저장소와 검토 화면. 클릭은 정답이 아니며 명시적 확인과 미확인·거절을 구분. 창작 업로드는 별도 권한/보존 정책.
4. 후속: 검증된 과거 Query를 추천 근거로 사용. 작품·판본 편향, 반복 중복, 데이터 삭제·보존 기간 설계 후 서버 수집 도입.

## 첫 버전 계약

- 상위 20개에서 최대 3개 제안. 총점 75, Melody Interval 80 이상 후보만 검토. 미보정 파일럿 임계값이며 정답 확률이 아니다.
- 6–32음, 서로 다른 음높이 4개 이상. 동일 조옮김과 템포 .25–4배에서 보존 음높이/음가와 새 Query 전체 onset을 검증.
- 한 내부 음 추가, 한 음 ±1/±2반음 또는 ±12반음 변경. 기존 쉼표 경계에 삽입하지 않으며 Include Rests 설정을 따른다.
- 타이/tuplet/cue 입력, Exact 옵션, rhythm/contour 모드에서는 생략. 확정 장식음/화성 분석이 아니다.
- 후보가 하나여도 전체 대응 검사 통과 시 제안. 복수 원본의 같은 제안을 우선하고 sourceId 중복 지지를 제외한다.
- 추가 검색 요청은 없다. 후보와의 보완 후 완전 대응은 전체 DB 검색 성공률이 아니다.
- 검색 당시와 현재 Query가 다르면 숨기고 새 검색 중에는 이전 추천을 숨긴다. 적용은 편집 history로 Undo/Redo 가능. 재검색은 사용자가 실행.

## 사례 보존

musicanote-query-suggestion-case v1 JSON: 원래/추천 Query, 변경 음 ID·유형·이유, 알고리즘 버전, sourceId/workId/streamId, 마디 범위, 음표 onset·음가 snapshot, 정렬, 조옮김·템포 근거, 사용자 명시적 확인.

서버 자동 수집 없이 사용자 저장 버튼으로 내려받는다. 파일 다운로드는 Harness 등록이 아니며 이후 공통 사례 import/컨텍스트 캡처 어댑터로 연결할 계획이다. snapshot은 선율 재현용으로 원본 MusicXML 전체 기보·앞뒤 마디를 담지는 않는다. 원본 식별자와 근거로 추가 캡처가 가능하다. source snapshot은 기존 검색 응답에서 제공한 구간에 한정한다.

## 검증 및 제한

양성/음성 회귀로 조옮김·템포·누락·옥타브·쉼표·Exact 옵션·다중 오류·불완전 정렬을 확인한다. 기존 Notation과 audioPlayback을 재사용한다.

기대 곡이 후보에 없으면 추천으로 구제할 수 없다. 삭제 음가를 이웃 음에 흡수한 경우, 짧은 Query, 복수 오류, 두 음 누락, 복잡한 프레이즈 이동은 후속 평가 범위다. 운영 추천 품질은 실제 사례 확인이 필요하다.

2026-09-16 검증: 관련 회귀 32개 통과, production build 성공. 기존 double-ornament v2/v3의 저장 응답 51개를 재생한 결과 원형 17개 추천 0, 한 음 삭제 17개 추천 17 및 모두 원형 복원, 두 음 삭제 17개 추천 0이다. 이는 기존 편의 표본이며 검색을 새로 실행한 실험이나 일반 오추천률 측정은 아니다.

재현: node scripts/evaluate-query-completion.mjs. 결과와 Query/추천/evidence는 evaluation/reports/query-completion-v1/replay.json에 보존한다. 브라우저 자동화 런타임 연결 실패로 실제 클릭·청각 검증은 미완료다.

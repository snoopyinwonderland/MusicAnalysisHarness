# 단순 패턴의 리듬 우선 정렬

2026-09-17 사용자 요청: 순차진행/동음반복은 같은 음높이 형태가 흔하므로 리듬을 더 강하게 구별한다.

## 적용 범위

- melody_rhythm 모드이며 타이 병합 후 6개 이상의 음 전체가 한 방향 1~2반음 순차진행 또는 동일 음 반복인 Query만 적용한다. 기존 허용 옵션의 안내 정책을 유지한다.
- 일반 멜로디·melody only·rhythm only·contour 모드의 기존 배점은 변경하지 않는다. 내부에 일부 반복/순차 구간만 있는 Query도 기존 방식이다.
- 단순 패턴 전용: 음정 유사도 90점 미만은 제외하고, 국소 점수와 순위는 멜로디 정렬 30% + 리듬 70%를 기준으로 한다. 멜로디 정렬은 기존 local alignment와 interval 혼합이다. 보조 순위 보정은 ±1점 이내다. 기본 Similar 상한 97과 Exact/명시적 exact 옵션의 기존 그룹 정책은 유지한다.
- 실제 duration과 음 사이 간격을 하나의 공통 템포 비율로 비교한다. 로그 비율 중앙값으로 템포를 구하고 3% 이내 오차를 허용한다. 부분 대응은 coverage만큼 감점한다. 긴 음가를 잘라 같은 클래스로 만드는 기존 관대한 리듬 점수 대신 이 점수를 단순 패턴에만 사용한다.
- 합성 대조에서는 전체 템포 확대가 100, 작은 음가 오차는 큰 음가 변화보다 약한 감점, 긴 음·쉼표 변화는 구별된다. 70%/90점은 운영 초깃값이지 대규모 보정 완료값이 아니다.

## 실제 검증과 제한

- evaluation/reports/pattern-rhythm-v1: 최초 A/B Query와 전체 응답 보존. 리듬만 강화하자 interval 약 78.5인 후보가 1위가 되어 멜로디 하한이 필요함을 확인했다.
- evaluation/reports/pattern-rhythm-v2: 멜로디 하한 추가 후 A/B 모두 완료. 새 반환 100개 모두 음정 90점 하한 준수 확인. 이전 1위 Violin Concerto No.1 Op.34(94.07점) 대신 2 Konzertetüden S.145(80.37점)가 1위가 됐다. 리듬 산식도 바뀌었으므로 구/신 리듬 점수를 같은 척도로 직접 비교하지 않는다. 음악적 관련성의 사람 검토와 대규모 회귀는 남아 있다.
- 베토벤 원본은 두 설정 모두 hits=true, candidates=false, 반환 순위 없음이었다. 후보 선별 누락은 아직 해결되지 않았다. 기존 테스트 파일은 덮어쓰지 않았다.
- 베토벤 EM09-L12 원형은 변경 전 hits에는 있지만 candidates에 없다. 순위 점수 변경으로 후보 누락을 해결했다고 주장하지 않는다. EVAL-007 후보 선별 개선은 계속 미해결이다.
- 관련 32개 테스트와 빌드 통과. 새로운 대규모 305회 회귀는 아직 재실행하지 않았다. 과거 결과 수치를 새 알고리즘 성능으로 재사용하지 않는다.

# 실제 사례: 기존 DB 리포트 실행 v1

## 목적과 범위

사용자 요청에 따라 기존 DB에 참조곡이 확인된 Twinkle → Ma Boy, When Love Takes Over → Clocks, Jesus of Suburbia → Summer of '69를 먼저 검사한다. 입력 원본과 운영 DB는 변경하지 않는다. 21 Guns와 Johnny B. Goode 쌍은 이번 실행에 포함하지 않는다.

실행은 `evaluation/reports/real-pairs-existing-v1/`에 보존한다. 각 입력에서 파서가 우선순위로 고른 하나의 선율 스트림과 최대 7개 Phrase를 사용한다. **전곡·전성부 검사 완료가 아니다.** 입력의 알려진 DB 판본은 검색 반환 후 제외하고 별도 저장한다. 이 방식은 후보 생성 단계의 자기 일치 경쟁까지 없애지는 못한다.

전체 검색 결과는 `search.json`, 상세 비교는 상위 10개 후보 그룹의 `report/index.html`에 보존한다. 참조곡 목록은 실행 후 회수 여부 평가에만 쓰며 후보 선택이나 점수에 넣지 않는다. 구조 분석 실패, 검색 실패와 정상 검색의 무결과를 구분한다.

## 재현

1. `scripts/prepare-real-pair-uploads.py`를 실행하여 manifest의 사용자 XML을 기존 파서로 읽는다. Python 경로는 실행 환경에 맞춰 지정한다.
2. `node scripts/run-real-pair-reports.mjs <입력 디렉터리> <새 출력 디렉터리>`를 실행한다.
3. `node scripts/verify-preclearance-report.mjs <각 사례의 report 디렉터리>`로 SVG 타깃과 오디오 스케줄 검사를 수행한다. 이는 사람의 청취·시각 판독을 대신하지 않는다.

원본 경로, 스트림 목록, 입력 해시, 구조 스냅샷, 선별 Query, 검색 결과, 자기 일치 제외 내역과 생성 리포트를 연결하여 남긴다. XML의 이벤트 표현을 기반으로 비교 악보를 재기보하므로 원본 조판과 동일하다는 보증은 없다. 개인 악보와 생성된 음표 자료를 공개 저장소에 자동 게시하지 않는다.

## Twinkle: 분산된 변형 유사성 핵심 사례

사용자는 이 사례를 단일 완전 일치보다 중요한 검증으로 지정했다. 관찰은 “완전히 같은 멜로디는 아니지만 비슷한 느낌이 군데군데 계속 나온다”이다. 기계가 읽을 수 있는 원문·유형·검토 요구사항은 `evaluation/real-cases/five-pairs/twinkle-review-brief.json`에 별도 보존한다. 이 관찰은 검토 가설이지 법적 양성 정답이 아니다.

검증할 구분:

- 한 구절의 반복 대 서로 다른 구절들의 유사성: 반복 횟수를 독립된 증거 수로 합산하지 않는다.
- 국소 변형: 치환·생략·삽입·옥타브 이동·음가 변화 뒤에도 유지되는 음정, 윤곽, 리듬형, 기둥음의 구체적 위치를 제시한다.
- 분산 범위: 입력곡과 비교곡 양쪽의 구간, 겹침을 제거한 비중, 등장 순서를 남긴다.
- 흔한 관용 음형 대 특징적인 결합: 같은 분위기나 흔한 리듬의 반복만으로 강한 경고를 만들지 않는다.
- 회수 실패 대 구간 비교 실패: 전체 DB에서 못 찾았는지, 선별이 관련 Phrase를 빠뜨렸는지, 후보에는 있었으나 순위에서 밀렸는지 구분한다.

### 이번 기준선과 후속 개선의 경계

이번에는 기존 검색을 그대로 실행하여 기준선을 만든다. 분산 유사성 전용 탐지기가 이미 검증됐다고 주장하지 않는다. 다음 평가는 선별에서 빠진 Phrase의 범위, 서로 겹치는 경계 창, 다수의 약한 일치를 묶을 때의 오탐을 함께 확인해야 한다. 알려진 주석 구간을 직접 비교하는 진단은 가능하지만, 이는 블라인드 검색 회수 성과와 별도로 표기한다.

Twinkle에만 점수를 보정하거나 Ma Boy를 강제로 넣지 않는다. 개선 규칙은 다른 변형 사례와 흔한 음형의 음성 대조군에도 같은 조건으로 적용해야 한다.

## 실행 상태

Twinkle 기준선 완료: 7개 Query 모두 정상 완료, 59개 후보 source 그룹, 알려진 자기 일치 2건 별도 보존. Ma Boy(KY 76909)는 반환 결과에 없었다. 14–15마디를 포함한 Query도 검색했으므로 해당 부근을 전혀 검사하지 않은 것은 아니다. 후보 생성/허용 조건/반환 30개 제한 중 어디서 누락됐는지는 아직 확정하지 않았다.

선택 성부의 439개 attack 중 직접 검색 Query에 포함된 고유 attack은 175개, 같은 형태의 반복 위치까지 대표되는 attack은 329개이다. `coverage-audit.json`에서 마디·시간·이벤트 ID·반복·미검사 ID를 확인할 수 있다. `scripts/audit-real-pair-report.mjs`로 동일 감사를 재현한다. 반복 대표 범위는 독립 검색 수나 독립적인 침해 근거 수가 아니다.

Twinkle 상세 비교는 상위 10개 후보, 10개 match, 20개 비교 SVG를 생성했다. 타깃 SVG ID, 스크립트 구문, 테스트 AudioContext의 음높이·시간 및 연속 재생 취소 검사를 통과했다. 실제 브라우저 청취·원본 조판 시각 검증 완료를 뜻하지 않는다.

When Love Takes Over: 7개 Query 정상 완료, 113개 후보 source 그룹, Clocks 미회수. 401개 attack 중 직접 검색 157개, 반복 포함 대표 범위 201개이다. 상위 10개 후보의 20개 비교 SVG와 오디오 스케줄 검증을 통과했다.

Jesus of Suburbia: **검색 미실행**. 준비 도구가 XML의 여러 박자를 하나의 `unknown` 값으로 전달했고, 구간별 박자가 전달되지 않아 사용 가능한 Phrase가 `meter-needs-review` 등으로 제외됐다. 824개 attack에서 선택 Query 0개, `needs-review`이다. 이는 Summer of '69 미회수 시험조차 완료한 것이 아니다. 구간별 박자와 변박 경계 처리 후 재실행해야 한다. 임의로 4/4를 넣어 통과시키지 않았다.

실제 조회가 완료된 것은 2곡, 총 14개 Query이다. `evaluation/reports/real-pairs-existing-v1/review.html`에 완료/미실행 상태와 리포트 링크를 모았다. 기존 400개 변형 Query 성공률과 이번 실곡 프레이즈 검사 결과를 혼합하지 않는다. 중요한 후속 과제는 Twinkle의 후보 회수 실패 분리 진단, 실제 참고 구간과의 대조, 복수의 비동일 구절 집계 검증이다.

# 실곡 진단 실행: 후보 회수, 정교한 contour, 프레이즈 독립 구간

## 변경 원칙

특정 작품명·ID·마디를 검색 점수/후보에 주입하지 않는다. 참조곡 ID는 실행 후 로그를 읽는 평가기에만 있다. 기존 입력과 DB는 보존하고, 실패한 실험도 새 디렉터리에 남긴다. 아래 실험은 법적 침해 판정이 아니다.

## 1. 입력 감사와 변박 보완

`scripts/audit-real-pair-inputs.py`로 제공된 5쌍 10개 XML의 성부/음표/표시 마디/ordinal/박자를 `evaluation/runs/real-pair-input-audit-v1/`에 기록했다. 모두 두 검색 성부로 파싱됐다. 기존 검사는 첫 번째 성부만 사용했다. 이것이 항상 실제 주선율이라는 청취 확정은 하지 않았다. 화음 동시 onset은 상단 음을 보존하는 파서 특성이며, 이조 악기의 실음 검증은 별도 과제다.

준비 도구에서 마디별 박자와 표시 번호/ordinal을 분리 보존한다. 구조 어댑터 v2는 박자 정보의 변경도 스냅샷 무효화에 반영한다. 단일 박자로 이루어진 Phrase는 변박 곡 안에서도 검색할 수 있고, 중간의 쉼 구간에서 발생한 변박까지 포함해 서로 다른 박자가 걸친 Query는 보류한다. 박자/시작 박 위치가 다른 반복은 같은 Query로 합치지 않는다(selection v3).

이 보완으로 Jesus of Suburbia는 Query 0개에서 7개로 실행 가능해졌다. `evaluation/reports/real-pairs-meter-v2/RC-005/`에서 7개 검색 완료, 117개 후보 그룹, Summer of '69 미회수. 상위 10개 후보의 20개 SVG와 테스트 AudioContext 스케줄 검증 통과. 824 attack 중 직접 검색 154개, 반복 포함 대표 203개이다. 이 실행은 이후 추가된 시작 박 위치별 중복 분리 변경 전 selection v2로 실행되었으며, 후속 실행과 동일 설정으로 혼합하지 않는다.

## 2. 기존 Twinkle 후보 탈락 추적

`scripts/trace-real-pair-search.mjs`가 기존 7개 Query를 동일 조건으로 재실행했다. 추적을 켜기 전/후 결과 객체는 7개 모두 같았다. 전체 진행: `evaluation/runs/twinkle-stage-trace-v1/`.

- Ma Boy는 7개 모두 정밀 비교 후보에 들지 못했다. 2개 Query에서는 초기 hit에 존재했지만 후보 선택에서 빠졌다.
- 참조 스트림에는 공통 interval 3-gram 및 contour 3-gram이 실제 존재한다. 공통 토큰의 제한된 앞부분 행을 읽는 방식과 이후 후보 상한이 누락 원인이다. 모든 Query의 모든 누락을 단일 원인으로 축약하지 않는다.
- DB Ma Boy는 6개 성부로 확인되며 제공 피아노 XML은 2개이다. 같은 판본/좌표/성부라고 가정하지 않는다.
- 참조곡을 지정한 직접 정렬은 `pair-alignment.json`에 별도 보존했다. 이것은 전체 DB 회수 성공이 아니다.
- 첫 진단 실행에는 시작 시 코드 해시 기록이 없었다. 이후 runner에 코드 해시/DB 지문/환경 설정 기록을 추가했다. 나중에 계산한 해시를 실행 당시 기록이라고 소급 주장하지 않는다.

## 3. 정교한 contour 후보 보충 — 실험, 기본 비활성

`server/contour-seeds.mjs`는 다음을 분리한다: U/D/S 편집 유사도, 음표 순서에 따른 정규화 높이 곡선, 같은 방향 연속 구간의 순서, 구간 내부 대표 간격 대비 상대적 도약/반복. 쉼표는 피치 윤곽 계산에서 제외하고 리듬은 기존 최종 비교가 담당한다. 전체 조옮김·옥타브 이동에 불변이며 모든 음이 같은 경우는 저정보로 표시한다. 정식 Schenker 분석이나 완성된 contour 검색 UI가 아니다.

전체 DB 기반 부가 색인 `data/search-index-v2/contour-sidecar-v1.sqlite`: 385,163 성부, 81,236,261 음, 250,052,608 bytes. 원래 DB는 읽기 전용, 새 색인 생성에 1 GiB 상한을 적용했다. `MUSICANOTE_CONTOUR_SIDECAR`를 명시한 실험 프로세스에서만 사용한다. DB 지문이 바뀌면 캐시된 색인도 거절한다.

실험은 5/7방향 길이의 윤곽 seed와 구간별 상세 윤곽 비교로 상위 120개 성부의 후보를 보충했다. 추가 후보의 retrieval bonus는 0이며 최종 정렬·허용·점수 기준은 바꾸지 않았다. `evaluation/runs/twinkle-contour-seeds-v1/`에 7개 재검색과 `recall-audit.json`을 보존했다.

결과: **Ma Boy 미회수. 기본 적용 보류.** 5개 Query는 기존 저정보 판정으로 보충이 생략되고, 2개에서 보충이 실행되어 반환 결과는 달라졌지만 참조곡은 없었다. 두 보충 검색의 총 실행 시간은 약 85.5초, 48.9초였다. 같은 조건의 반복 분포 측정이 아니므로 단정적인 성능 비율로 사용하지 않는다.

추가 진단: 해당 두 Query의 윤곽 상한 전 목록은 40,527/52,508 후보로 넓었다. Ma Boy의 일부 성부 순위는 17,074/41,859로 상한 밖이었다. 상한만 늘려 해결하지 않는다. 고정 길이 창이 삽입음에 취약한 점, 흔한 방향 패턴의 과다 후보, 정보량 판정과 정교한 음악적 정렬을 결합할 필요가 있다. 직접 지정 비교의 한 예에서 가변 길이 contour 81.3점이 같은 길이로 자르면 73.8점이 되지만, 이는 정답 점수 목표가 아닌 일반 창 길이 문제의 진단이다.

## 4. Phrase 외의 검색 단위

`selectStructureQueries`와 오프라인 runner에 `segmentStrategy`를 추가했다.

| 값 | 방식 |
|---|---|
| phrase | 기존 Phrase 중심, 기본값 유지 |
| windows | 8·12·16·24개의 연속 attack을 50% 겹침 창으로 준비 |
| hybrid | Phrase + 중복되지 않은 연속 창 Query |

단일 전략은 기존 최대 7개 선별 예산, 혼합은 최대 14개이다. 생성 예산은 400개 창이며 길이별 round-robin으로 준비하고 미준비 수를 기록한다. **준비한 창 모두를 검색했다는 뜻은 아니다.** Window는 Phrase 확정 분석이 아니고, 원본 음표를 건너뛰지 않는다. 쉬는 시간과 원래 attack ID를 보존하며 마지막 음의 길이가 다음 attack과 겹쳐도 선택하지 않은 음을 창에 끌어오지 않는다.

겹친 창의 음표/음가 비중은 합집합으로 집계해야 하며 창 개수를 독립 Phrase 개수로 바꾸지 않는다. 파생 window 정의는 분석기의 확정 unit과 구분하여 선택 결과 `generatedUnits`에 보존한다. 이 보존 필드는 최초 windows 실험 프로세스가 시작한 뒤 추가됐으므로 최초 실험은 별도 window-bank 파일로 보완한다.

실행 예:

```text
node scripts/run-real-pair-reports.mjs evaluation/runs/real-pairs-existing-v2-inputs <새 출력 폴더> RC-004 windows
```

새 웹 검사 API/업로드/선택 버튼은 연결하지 않았다. 사이트의 로컬 사전검토 페이지에는 실제 가능한 오프라인 방식과 이 제한을 안내한다.

Twinkle windows 첫 실험은 272개 창을 준비하고 7개를 선별했다. 선택 길이는 12·16·24음이며 구간은 11–14, 16–21, 21–23, 24–28 등에 분포한다. 반복/길이 기반 7개 선별이 전체 범위를 충분히 대표하는지도 별도 검증 대상이다. 실행 결과는 `evaluation/reports/real-pairs-windows-v1/`에 저장한다.

## 남은 일

첫 구절의 사용자 지정 비교와 이후 유사 구절들의 전개 순서를 평가하라는 추가 요구는 [첫 구절·전개 검토](twinkle-first-region-and-sequence-review.md)에 이어 기록했다. 원본/보정 마디 번호는 확인 대기이며 전체 반전 진단은 검색 가중치와 분리한다.

1. 여러 길이와 경계를 다루는 Query의 검사 범위를 확대하되, 처음 7개 선택과 미검사/페이지 재개를 명확히 분리한다.
2. 긴 선율의 고유 음높이 비율 때문에 저정보로 분류되는 문제를 대조군으로 검증한다. 반복음 엄격 조건의 전면 해제는 하지 않는다.
3. 가변 길이/삽입음에 견디는 후보 특징과 멜로디·리듬 증거를 함께 검증한다. contour 상한이나 점수를 이 사례에 맞춰 조정하지 않는다.
4. 독립된 여러 유사 구간의 작품 단위 집계 및 나머지 실곡/음성 대조군 평가. Ma Boy 회수 목표는 아직 달성하지 않았다.

관련 테스트 124개 및 TypeScript 검사 통과. SVG/오디오 검증은 프로그램 검증이며 사람의 청취 판독 완료가 아니다.

## 연속 구간 실험 완료 기록

`real-pairs-windows-v1/RC-004`는 7개 검색 모두 완료했고 실패는 0개다. 후보 81개 그룹, 자기 일치 6건을 분리했으며 Ma Boy는 여전히 회수되지 않았다. 439개 attack 중 직접 검사한 합집합은 104개, 반복 대표를 포함하면 255개다. 전체 악보를 검사한 결과로 해석하지 않는다. 상위 10개 비교의 SVG 20개, 강조 대상 존재, 테스트 AudioContext 스케줄/취소 검증을 통과했다. 272개 창의 정의는 별도 `window-bank.json`에 보존했다. 다음 과제는 선택 예산 때문에 빠지는 범위와 후보 검색 단계의 누락을 구분해서 개선하는 것이다.

# 사전검토 3단계: 후보 구조 중요도 비교

## 최신 상태: 2026-09-15 worker 적용 후

아래 최초 실행의 6개 보류는 후속 실행에서 모두 해소됐다. `structure-worker.mjs`가 원본 읽기와 구조 분석을 수행하고 기존 worker client가 timeout/Ctrl+C 시 종료한다. 성부당 기본 60초, 최대 50,000음이며 CLI `--timeout-ms`, `--max-notes`로 제한 내 조정할 수 있다. timeout은 후처리/저장 전체의 deadline은 아니다.

- 관련 5개 테스트 파일, 29개 테스트 통과(취소, timeout 후 worker 재생성 포함).
- `evaluation/runs/preclearance-importance-worker-2026-09-15.json`: 26그룹/30성부/56구간 완료, 실패 0.
- 이전 성공 50개 candidateImportance가 동일하고 기존 검색 순위·점수·targets·alignment·coverage도 동일함을 대조했다.
- 이번 warm 실행 보강 시간 약 2.02초. 최초 실행과 캐시 조건이 달라 속도 향상 배율로 해석하지 않는다.
- 스냅샷 31개, 총 35,708,254바이트. 이전 보고서/스냅샷도 삭제하지 않았다.
- 취소 시 처리하지 않은 match는 cancelled, timeout/분석 실패는 needs-review로 보고한다. 구조 보강의 영속 resume는 아직 없다.

인수인계는 [문서 지도](README.md)와 [재현 가이드](REPRODUCIBILITY.md)에서 시작한다. 다음은 구조 중요도·관용구 변별력 기반 검토 우선순위 검증이다.

## 구현 범위

입력과 후보에 같은 `analyzeStructureSnapshot` 어댑터를 사용한다. 구조 분석기 버전과 코드 지문을 증거에 보관한다. 현재는 별도 오프라인 보강 단계이며 사이트의 검색 순위와 UI는 변경하지 않는다.

- 후보는 검색 조각이 아닌 전체 인덱스 성부를 읽는다. 인덱스에서 타이는 이미 논리 음표로 합쳐져 있다.
- 조각의 임시 음표 ID를 재사용하지 않는다. onset+MIDI가 유일하게 일치할 때 전체 성부 음표 ID에 연결하고, 누락·모호성은 검토 대상으로 남긴다.
- 선택 음 사이의 모든 음표를 포함한 연속 구간으로 비교한다. 띄엄띄엄 선택된 음만으로 새로운 모티프를 만들지 않는다.
- 반복은 조옮김과 균등 시간 배율을 허용하되 음가와 onset 간격을 함께 비교한다. 겹치는 반복은 중복 집계하지 않는다. 현재 변형 반복은 별도 탐색하지 않는다.
- 음가·박자 휴리스틱은 실제 박자와 성부의 중앙 음가를 사용한다. 후보의 박자 변경은 XML 마디 순서로 전달한다. 미상 박자는 4/4로 채우지 않는다.
- Phrase/Motif 포함·겹침 관계를 근거로 제공한다. 이것을 곧바로 형식적 중요도나 사람 분석의 확신도로 해석하지 않는다.
- 종지, 형식 위치, 기둥음, 멜로디 역할은 아직 null이다. 양쪽에서 관측된 공통 항목만 가중치를 재정규화해 비교한다.
- 비중은 해당 스냅샷 성부 안의 음 수와 음가 합계에 대한 비율이다. 작품의 모든 파트를 포함한 중요도가 아니다. 입력이 부분 악보이면 그 범위 안의 비중이다.
- 중요도는 보정되지 않은 휴리스틱이며 침해 확률이 아니다. 기존 유사도, 순위, alignment는 그대로 보존한다.

## 실행

```powershell
node scripts/analyze-preclearance-candidates.mjs evaluation/runs/preclearance-structure-2026-09-14.json evaluation/runs/preclearance-grouped-2026-09-14.json evaluation/runs/preclearance-importance-2026-09-15.json
```

출력과 `.assets` 폴더는 반드시 새 경로여야 한다. 기존 보고서를 덮어쓰지 않는다. 인덱스 size/mtime, 입력 보고서 지문, 분석 코드 지문을 기록한다. 스냅샷의 sourceHash는 정규화된 인덱스 입력의 지문이며 원본 XML 바이트 지문이라고 주장하지 않는다. 음높이·음가·시점·표기·마디 및 구조 근거를 보존하지만 원본 전체 MusicXML 레이아웃 복제와는 구별한다.

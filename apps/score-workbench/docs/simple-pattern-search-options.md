# 순차진행·동음반복 검색 허용 옵션

2026-09-17 사용자 요청. 상세 검색에 연속 순차 진행 검색 허용(allowContinuousStepwise), 연속 같은 음 검색 허용(allowContinuousRepeated)을 추가했다. UI 기본값은 둘 다 false이며 Query JSON 복사와 세션 복원에 보존된다.

## 범위와 호환성

- 멜로디/멜로디+리듬 검색만 적용. 타이 병합 후 attack 6개 이상이고 전체가 한 방향 ±1/±2반음 순차진행, 또는 전체가 동일 MIDI 음높이인 경우만 해당한다. 실제 쉼표 간격이 있으면 연속으로 보지 않는다. 쉼표 제외 옵션에서는 삭제된 쉼표 간격도 없어지는 기존 정책을 따른다.
- 미허용 시 빈 결과와 queryNotice 안내를 반환한다. 허용하면 기존 검색을 실행하며 점수·후보 폭·Exact 조건·동음반복 하한을 완화하지 않는다. 원곡 반환 보장이 아니다.
- 일부 구간의 반복이나 방향 전환을 포함한 일반 선율은 차단하지 않는다. 이는 정보량 안내용 보수적인 규칙이며 음악학적 고유성/저작권 판단이 아니다.
- 기존 Harness/내부 분석/API와 재현성을 위해 필드 생략은 기존 동작을 유지한다. 새 UI는 명시적 false를 보낸다. 과거 평가 JSON과 응답은 수정하지 않는다.

## 베토벤 사례와 검증

EM09-L12-original: MIDI 59,60,62,64,66,67,69,71,72,73,74,76. 같은 방향의 순차진행이다. 과거 후보 누락은 이 새 규칙 때문이 아니며 기존 엔진에는 명시적인 순차진행 차단이 없었다. 따라서 정책상 제외와 후보 선별 손실을 혼동하지 않는다.

- server/query-pattern-policy.test.mjs: 6개 테스트 통과(순차/반복/혼합/허용 독립성/레거시 및 모드/쉼표).
- 실제 베토벤 Query를 searchDatabase에 전달하여 허용 안내 반환 확인.
- npm run build 통과. 브라우저 수동 클릭 검수는 미완료.

## 미반영 개선 항목 현황

최근 5개 배치 305회(65+30+90+60+60)의 통합 보류 목록은 EVAL-001~008 총 8개 원인별 항목이다. 독립 멜로디 305개나 오류 305개라는 뜻이 아니다. 7개는 보류, EVAL-004는 평가 기록에 적용했으나 사용자 UI는 보류다. 전체 과거 개발사의 모든 미완료 항목을 합산한 수치는 아니다.

1. Exact 판정에서 실제 음가·쉼표 차이를 엄격히 구분.
2. 삭제·음가 흡수에서 긴 음과 도착 위치의 정렬 개선.
3. 동음 분할/합침의 대응과 표시.
4. 같은 작품의 반복 구간과 대표 위치 구분(UI 보류).
5. 국소 옥타브 변경과 음 누락을 구분.
6. 낮은 정보량 Query의 엄격 하한과 삭제 후 박자 이동 충돌.
7. 초기 후보 검색/축소에서 원곡 누락.
8. 같은 음정·다른 리듬의 반복 중 잘못된 대표 구간 선택.

이번 옵션은 별도 명시적 사용자 정책이며 위 8개 문제를 해결한 것으로 처리하지 않는다. 문제·근거·제안은 search-evaluation-improvement-backlog.md와 독립 export에서 연결한다.

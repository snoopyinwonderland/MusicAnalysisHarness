# 두 작품 지정 · 기존 시스템만의 비교

2026-09-15 요청: 사용자 의견·평가·지정 마디를 배제하고 기존 검색 시스템만 사용한다.

## 실행

`scripts/run-system-pair-comparison.mjs`는 기존 파서의 제공 XML 감사 자료에서 음표만 읽고 원본 두 개를 독립 색인에 보존한다. 기존 `build-search-sqlite.mjs`, 구조 분석 어댑터, `selectStructureQueries`, `searchDatabase`를 사용한다. production DB는 변경하지 않는다. 별도 segment-comparison 모듈, 회색지대 라벨, 사용자 지정 구간은 읽지 않는다. 상대 곡의 두 파싱 성부로 scope를 제한한다. 두 곡 색인의 토큰 빈도/후보 경쟁은 전체 DB와 다르므로 전체 DB 검색 성공이나 동일 순위로 해석하지 않는다.

## Query 선택 — 실제 구현 기준

각 곡의 두 파싱 성부별로 Phrase와 8/12/16/24 연속음(50% hop) 창을 혼합한다. 단일 전략당 최대 7개. 7음 미만, 48음 초과, 반복음 전이 비율 65% 초과, 음정 종류 3개 미만, 박자 미확인 후보를 보류한다. 동일 음정/상대 음가·박자/시작 박 패턴은 묶는다.

선택 점수는 55% 중요도(현재 실제 입력은 성부 role과 반복 횟수), 35% 길이 지지(12음에서 포화), 10% 해당 성부 음가 점유율이다. 구조 위치·종지·기둥음 중요도는 선택 단계에서 현재 null이며 계산에 넣지 않는다. 이는 검색 후 점수의 Downbeat/Schenker-informed와 별개다. 낮은 후보 중복화를 위해 같은 전략 내 70% 초과 겹침을 제외한다. 혼합 시 완전히 같은 signature만 추가 제거하므로 전략 간 겹침은 남을 수 있다.

Twinkle P1:1:1 = Phrase 7 + 창 7, P1:2:2 = 4+7. Ma Boy P1:1:1 = 7+7, P1:2:2 = 4+3. 총 46 Query. 전체 전수 검사가 아니고, 선별 편향/미검사 범위가 남는다. 대상과 비교하기 전에 Query가 결정된다.

## 결과와 표시

`evaluation/reports/twinkle-system-only-v1/`: Exact 0, Similar 10개 반환, 최고 검색 ranking 78.10395. 양방향/겹치는 Query가 있으므로 10개 독립 유사 구간이라는 뜻이 아니다. 전체 작품 점수·법적 판정은 없다. HTML은 `export-system-pair-comparison.mjs`로 생성. 실제 alignment 대응 음표를 붉게 표시하고 비교용 재기보/합성음 재생을 제공한다. 20개 악보에서 note 및 모든 강조 ID 존재, JavaScript 구문 검증 완료. 육안/청취 완료 주장은 하지 않는다.

기존 사용자 평가 포함 페이지는 보존하되 새 페이지와 분리한다. 모든 Query, 선택/보류 이유, 결과·탈락 진단, 엔진 해시는 report.json 및 task 파일에 보관한다.

# Twinkle–Ma Boy 첫 구절 및 연속 전개 검토

## 사용자 관찰과 범위

2026-09-15: Twinkle 10마디부터 14마디 첫 음까지, Ma Boy 10–13마디. 정확히 같은 음들은 적지만 선율과 리듬이 매우 비슷하게 들린다는 청취 관찰. 이후 구절에서도 변형된 유사성과 비슷한 진행이 지속된다는 추가 관찰. 상행/하행 반전도 비교 대상으로 요청했다.

이는 사람이 제공한 유사성 가설이다. 의도적 차용이나 법적 침해가 확정된 라벨은 아니다. 이후 구절 좌표는 아직 전달되지 않았다.

추가 사용자 지침: 명확한 침해로 단정하기 어려운 회색지대 사례로 취급한다. `humanAssessment=gray-area`, 법적 정답 라벨은 미정이다. 이 두 곡이 침해로 나오도록 계산/가중치/임계값을 조정하지 않는다.

## 두 작품 웹 비교 초안

`scripts/export-twinkle-pair-preview.mjs`로 `evaluation/reports/twinkle-pair-preview-v2/index.html`을 생성했다. 첫 구절의 두 번호 해석을 선택할 수 있고, 항목별 실험 지표·Verovio 재기보·A/B 합성음 재생·시간 진행 막대를 제공한다. 악보 안의 이동 커서는 아니다. 양쪽 첫 성부에 16음/8음 hop 창을 적용해 2,862쌍을 비교하고 원형 음정 편집 순으로 양쪽에서 겹치지 않는 검토 후보 6개를 제시한다. 후보 개수는 확정 유사 구간 수가 아니며 전개 일치 판정도 아니다. 전체 16개 악보 출력에서 note 존재와 페이지 JavaScript 구문을 검사했다. 실제 사용자 브라우저의 청취/레이아웃 검증은 별도다. 원본 판면이 아닌 재기보이며 그림의 마디 번호는 원본 좌표와 다르다.

## 자료와 좌표 주의

제공된 두 피아노 XML의 P1:1:1을 비교한다. KY DB 판본과 동일한 마디라고 가정하지 않는다. 원본 XML은 1부터 번호가 있고 파서는 첫 못갖춘마디 보정으로 표시 번호를 하나 낮춘다. 따라서 사용자 번호가 원본인지 보정 화면인지 확인 대기 중이다.

- 원본 XML 10: Twinkle A♭3–A♭3–F4…, Ma Boy F4–F4–F4…
- 보정 화면 10: Twinkle B♭3–C4–B♭3…, Ma Boy B♭3–C4–D4…

두 해석을 모두 `evaluation/runs/twinkle-first-region-v2/analysis.json`에 보존했다. 앞뒤 9–15마디 문맥 음표, 원본 ordinal/label/보정 번호, 음높이/음가/onset/tie 정보를 저장한다. 전체 원본 XML 두 개도 같은 폴더에 복사하여 원래 쉼표·화음·다른 성부까지 재현할 수 있게 했다. v1은 초기 진단의 중앙값 정규화 민감도 문제를 남기는 역사 기록이며 v2를 현재 결과로 사용한다.

## 실제 음표에서 확인한 점 — 원본 XML 번호 기준, 잠정

1. **10마디: 높은 음 반복 뒤 하강.** Twinkle은 앞의 낮은 A♭ 반복 후 F–F–E♭–C–B♭–A♭, Ma Boy는 F 반복 후 D–E♭–D–C–B♭–G. 동일한 음정열은 아니지만 반복 고점에서 낮아지는 공통 형태가 있다. 후반 C와 B♭은 두 악보 모두 각각 3.5박, 4박 위치에 8분음표로 놓인다. 여기에 바로 앞의 내부 굴곡과 끝음 차이가 있다.
2. **12마디: 짧은 반복음 묶음.** Twinkle은 E♭/A♭ 두 높이 사이 큰 이동, Ma Boy는 C/B♭ 좁은 이동을 사용한다. 이동 폭은 확연히 다르지만 두 곡 모두 16분음표 반복 묶음이 집중된다. 같은 방향열보다 '언제 촘촘하게 반복하는가'라는 시간적 질감이 비교 근거가 될 수 있다. 반복음만으로 높은 점수를 주자는 뜻은 아니다.
3. **13마디: 8분음표 흐름으로 전환.** 둘 다 8개의 연속 8분음표로 이루어진다. Twinkle은 C–D♭ 왕복 뒤 하행하고, Ma Boy는 E♭ 반복 뒤 내려갔다가 다시 올라오는 차이가 있다. 12마디의 촘촘한 반복에서 13마디의 고른 흐름으로 바뀌는 순서는 일치한다.

따라서 잠정 설명은 **같은 음의 개수보다 반복 밀도, 리듬형의 전환 순서, 고점 이후 하강, 일부 동일 박 위치가 결합된 유사성**이다. 이 요소들은 일반적인 음악 어휘이기도 하므로 다른 작품 대조 없이 이 사례만의 독특함이나 높은 위험으로 결론 내리지 않는다. 음원 청취를 자동 검증한 결과가 아니며, 화성/가사/표현과 실제 기둥음의 기능은 아직 분석하지 않았다.

## 일반 비교 모듈에 반영한 것

`server/segment-comparison.mjs`: 전체 음표를 유지하는 원형/전체 반음계적 반전 비교를 별도로 출력한다. interval 편집, 상세 contour, 음가 비율, onset 간격 비율, 정규화 시간축의 유성/무음 및 음높이 대응을 분리한다. 합산 위험 점수나 검색 순위 보너스는 없다. 시간 정규화는 전체 구간 한 번이며, 유리한 음마다 방향/조옮김을 바꾸지 않는다. 반전은 `p' = c - p` 형태로 하나의 상수만 사용한다. 조성적 반전 및 부분 반전/역행은 아직 구현하지 않았다.

원본 번호 비교는 양쪽 35 attack이며 원형 interval 진단 64.7, 반전 55.1이었다. 보정 번호 해석도 원형 60.3, 반전 49.3이다. 이 미보정 수치는 청취 유사도나 침해 확률이 아니다. 현재 두 해석에서 전체 반전이 더 나은 설명이라는 근거는 없었다. 관련 테스트 10개 통과. 실제 DB 재검색/회수 성공은 이 작업으로 주장하지 않는다.

참고: [music21 Stream.invertDiatonic](https://music21.org/music21docs/moduleReference/moduleStreamBase.html)은 조성적 반전 구현을 별도로 제공한다. 여기서 구현한 반음계적 반전과 혼동하지 않는다. [ISMIR 2005 melody retrieval](https://ismir2005.ismir.net/proceedings/1005.pdf)은 선율 표현과 시간적 탄력성을 다루며, 위 진단 가중치나 수치를 검증해 주는 자료는 아니다.

## 여러 구절의 진행을 평가할 다음 일반 규칙

- 검색 단위의 경계와 무관하게 후보 구간 대응을 모은다. 현재 선택 7개만으로 전곡 검사했다고 표시하지 않는다.
- 입력 또는 대상에서 겹치는 대응은 중복 제거한다. 동일 원본 구간을 여러 번 찾는 경우와 서로 다른 원본 구간들을 순서대로 찾는 경우를 구분한다.
- 대응 구간들을 시간 순서로 연결하고 순서 보존, 상대 간격, 구간 길이와 리듬 밀도의 변화 순서를 측정한다. 순서를 뒤섞은 대응도 별도 대조군으로 둔다.
- 하나의 조옮김/반전 규칙으로 여러 구간이 설명되는지와 구간마다 임의의 새 규칙이 필요한지를 구분한다. 후자는 더 복잡한 설명이며 같은 근거로 세지 않는다.
- 단순 점수 합/두 배가 아닌, 독립 구간 수·합집합 커버리지·전개 순서·흔한 패턴 여부를 별도 보고한다. 최종 집계 가중치는 긍정/부정 및 순서 섞기 대조군으로 검증한 뒤 결정한다.
- 다음 구절을 받으면 이 관찰 기록에 이어 저장한다. 아직 제공되지 않은 구간의 유사성을 확정하거나 구현 완료로 표시하지 않는다.

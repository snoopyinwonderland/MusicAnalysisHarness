# 경계 독립 반복·변형 분석 — 구현 계획

## 목적 / 현재 상태

기존 Phrase 경계 검출은 유지한다. 경계로 잘라진 Phrase만 비교하던 registry의 한계를 보완해 **경계 입력을 받지 않는** 반복 후보 탐색기를 병행한다. 첫 구현은 오프라인 shadow 후보 탐색과 음가/쉼 치환 증거까지이며 운영 연결은 하지 않는다. 이전 계획 REPEATED_PHRASE_STRUCTURE_PLAN.md는 경계 보정·검토 원칙의 기준으로 유지한다.

최신 상태: 아래에 기록한 v1.15/v1.16의 좁은 일반 규칙만 운영 적용됐다. 이번 repeat-hierarchy는 별도의 오프라인 후보 생성/검토 모듈이며 운영 경계를 바꾸지 않는다.

## 반복 계층 검토 v0.1

`server/repeat-hierarchy.mjs`는 Phrase 경계를 입력받지 않는다. 4음 seed에서 상대 attack 간격을 먼저 비교하고 음정/윤곽 변형을 허용한다. 긴 도착음(지원 박자 기준2박 이상)에서 끝나는8–64음 범위를 만들고, 양쪽 attack 수 차이4개까지 동적 정렬한다. coverage80/melodic85/rhythm75는 미보정 필터이지 신뢰도가 아니다. 끝음 길이 차이는 허용하되 양끝 정렬을 요구하며 긴 쉼/호흡표기를 넘는 범위는 만들지 않는다.

짧은 공통 시작 반복이 더 긴 대응 범위에 포함되면 child/parent 참조를 남긴다. 이는 확정 Motif/Phrase 가족이 아니며 내부 모든 모티프를 추출한 것도 아니다. 이후 단계에서만 기존 경계를 연결하여 부분 frame 억제와 더 큰 반복 대응의 충돌, 대응된 경계의 쉼 차이, 반복 시작 누락을 기록한다. 기존 분리/상위 묶음 해석은 모두 보존하고 autoApply=false로 둔다.

후보 seed는 거리별로 악곡 전체를 순회하고 범위 비교는 seed별 round-robin이다. 기본250000 seed검사/20000정렬은 오프라인 예산이며 실시간 운영용이 아니다. 4000정렬에서는009의 큰 반복이 누락되는 것을 확인했다. 예산 증가는 정확도 개선으로 간주하지 않는다. 부분 실행/다수 대안 및 미보정 점수를 노출한다.

검증:009에서 사용자 선호32–39/40–47/48–55/56–65 범위4개가 모두 독립 후보로 회수됐다. 사용자 마디/index는 평가 스크립트가 결과 생성 후에만 대조한다. 20000정렬에서1334개 후보/partial이므로 정답 선택 성공이 아니라 recall 확인이다. 008은1731정렬/48후보로 주어진 범위 내 완료했다. 결과는 evaluation/reports/repeat-hierarchy-{008,009}-v1. 다음은 중복/과잉 후보 억제, XML 증거 검증, 전문가 대안 선택 및 기존 UI와 연결이다. 반복음 split/merge의 엄격한 의미 판정은 여전히 미완료다.

## 단계와 완료 조건

사용자 추가 방향: 같은 리듬형과 비슷한 선율 변형으로 주제가 확장되는 사례를 우선한다. **리듬형으로 후보를 찾고 → 약한 선율 변형을 비교**한다. 원형과 pitch가 정확히 같은 것만 seed로 삼지 않는다. v0.1에서는 정규화 attack 간격을 먼저 검사하고, 음정 차이 누적8/윤곽 방향 차이2까지를 탐색용 허용치로 둔다(미보정). 음가와 쉼의 배분은 정렬 후 별도 증거로 기록한다. onset 기반 리듬 seed만으로는 같은 리듬의 서로 다른 주제/반주를 구분하지 못하므로 선율·범위 검증을 생략하지 않는다. 실제 기보 리듬의 split/merge 채널은 R2 후속이다.

1. **R1 후보 탐색(이번 구현)**: 같은 단일 stream의 모든 attack 시작쌍을 예산 내 비교. 5음 seed에서 조옮김 불변 음정/윤곽/상대 onset 간격을 사용하고, seed 이후 여러 길이의 창을 정렬한다. Phrase번호/제목/마디 예외를 입력하지 않는다. 부분 창은 complete motif로 부르지 않는다. ALWAYS WITH ME의 index0/30 대응을 독립적으로 회수해야 한다.
2. **R2 변형 증거(이번에는 일부)**: 기존 melody/shape/rhythm/coverage 정렬을 재사용하되 새 채널은 점수에 합산하지 않는다. 대응 연속음의 onset 간격은 같으면서 duration이 줄고 inferred gap이 늘면 음가→쉼 치환 후보를 출력한다. 명시적 XML rest인지 별도 검증한다. 삽입/삭제·끝음 길이 차이 표시는 기존 비교기의 미보정 후보이다. 같은 음 분할/합침은 앞으로 묶음 정렬과 총점유시간 보존을 구현한 뒤 별도 검증한다.
3. **R3 범위 복원**: 여러 창의 겹침·앞뒤 확장·종결 후보를 검토해 core와 complete extent를 구별한다. 최초 길이창/최고 점수/beam 개수로 종결을 정하지 않는다. 창 끝은 인위적이므로 현재 terminal alignment만으로 종결 대응을 확정하지 않는다.
4. **R4 가족/재등장 registry**: 동일 구간의 겹친 창을 독립 occurrence로 중복 집계하지 않는다. 원형 및 승인된 변형에 직접 대조하며 변형의 변형으로 가족을 무제한 확장하지 않는다. 작품 내부 역할과 검색 식별력은 분리한다. 반복음만 있는 seed는 버리지 않되 low-information으로 표시한다.
5. **R5 기존 경계와 결합**: 위 분석이 끝난 뒤에만 기존 경계와 event ID로 연결한다. 대응 위치의 내부/외곽 차이를 리뷰 제안으로 출력한다. 실제 긴 쉼·호흡표기·사람이 승인한 경계는 보호한다. 원형 하나만으로 모든 재등장 경계를 강제하지 않는다.
6. **R6 검증 및 opt-in UI**: 사용자 선호 사례/반례를 재생하고 독립 작품에서 전문가 검토. false merge 우선, 경계 이동/유지·보류·후보 회수·지연시간을 각각 평가한다. 그 뒤 승인된 보정만 선택 적용하며 baseline으로 즉시 복귀 가능하게 한다.

## 데이터 계약과 예산

입력: source-linked 단일 attack stream(id, onset quarter, duration quarter, pitchMidi). tie는 누적된 attack 입력이라는 전제다. 관찰값은 수정하지 않는다. 비유한 수/음수 duration/역행 onset/중복 ID/동시 attack은 v0.1에서 거부한다(코드가 임의 voice를 고르지 않는다).

출력: source+snapshot+engine hashes, event ID 반열린 범위, seed 및 비교창, 채널별 점수, 정렬쌍, 음가/쉼 후보, low-information, 사용 예산/partial 상태. confidence로 점수를 포장하지 않는다. ID는 원본 snapshot revision에 귀속되며 XML 수정판 간 안정성을 주장하지 않는다.

기본 seed 길이5, 확장창12/24/32음, seed 검사250,000쌍, 정렬300회. 초기 값은 계산량 제한/후보 회수용이며 음악적 판정 임계값이 아니다. 결과가 partial이면 미탐을 비반복으로 해석하지 않는다. 현재 seed는 삽입/삭제가 seed 안에 있는 변형을 놓칠 수 있으므로 정확도 완성으로 부르지 않는다. 향후 다중 seed/리듬 seed/박자 정규화와 salience 기반 후보를 검토한다.

## 화성 없는 판단의 한계

종지, 비화성음 종류, 화성적 prolongation, 조성/해결은 이 모듈에서 판정하지 않는다. 음가가 쉼으로 대체돼도 Phrase 경계가 같다는 결론은 내리지 않는다. 화성 필수 사례는 harmony-required로 연결할 뿐 Core나 기존 경계를 수정하지 않는다.

## 검증 목록

합성 양성: 옥타브/조옮김, 끝음 길이 변화, 음가→쉼 치환, 멀리 떨어진 반복. 음성/보류: 다른 onset 간격, pitch 불일치, 긴 실제 휴지, ostinato·동음 반복, 앞부분만 일치, 잘못된 입력, 예산 소진. 실사례008을 회수하고007 화성 가설을 자동 판정하지 않는지 점검한다. 004–006은 개발 회귀이며 독립 holdout이 아니다.

## 문서와 재현

### 인접 짧은 음형의 변형 반복 (v1.16)

단독 짧은 단위(4–8음, 최대4기준박)가 다음 Phrase의 앞부분과 같은 음가/attack간격·윤곽을 보이고 음정 차이가2반음 이내일 때, 짧은 내부 쉼(최대0.5기준박)과 후속의 더 긴 종결 호흡(최소1기준박 쉼, 내부 쉼의2배 이상)을 함께 확인한다. 후속 구간은 단위의2배 이상 attack 수여야 한다. 긴 쉼/명시적 호흡은 보호하며 동일 음표 수·리듬 조건을 벗어난 변형은 억지로 합치지 않는다. `shortCell:false` 롤백 가능. 이는 제한적 일반 휴리스틱이고 모티프 가족/화성 종지의 확정은 아니다. 상세 사례·회귀 기록은 development-log.md와 short-cell-008-v1/case.json을 참조한다.

### 제한적 운영 적용 — 전체 반복의 음가/짧은 쉼 치환

사용자 승인에 따라 v1.15에서 `repeated-breath-rule.mjs`의 좁은 일반 규칙만 기본 활성화했다. 오프라인 가변 범위 후보를 일괄 병합하는 기능은 아니다. 기존 단일 Phrase와 인접 두 Phrase의 결합 범위를 frozen baseline으로 비교하며, 새 병합을 같은 실행의 기준형으로 승격하지 않는다.

조건: 양쪽8–64개 attack과 같은 개수, 전체 음높이 대응(공통 조옮김 대비2반음 이내)80% 이상, attack 간격 일치80% 이상, 첫/끝4음의 pitch 대응, 양쪽 끝의 최소1기준박 음가+뒤 쉼. 문제의 내부 경계는 최대0.5기준박 쉼과 최대1기준박 종결음이어야 하며, 기준형의 무쉼 지속음이 동일 attack 간격 아래 음가+쉼으로 재배분됐다는 국소 일치를 요구한다. 긴 쉼/호흡표기, 타이 continuation, 미상 박자/시간, overlap은 제외한다. 미보정 휴리스틱이며 화성/종지 판단은 하지 않는다.

비교 최대4096회, 결과에 근거와 partial을 남긴다. `analyzePhraseBoundaries(notes,{repeatBreath:false})`로 이 규칙만 비활성화할 수 있다. 현재는 동일 음표 수·동일 템포의 치환만 운영 적용하며 삽입/삭제/템포 변형은 계속 리뷰 전용이다. work ID·제목·특정 마디·절대 pitch 예외는 금지한다.

5개 저장 사례 대조에서008의 index35 한 경계만 억제되고004–007은 불변이었다. 이는 개발 회귀 범위이며 전체 음악 정확도 보장은 아니다. `evaluation/reports/repeated-breath-production-v1/regression.json`에 코드/원본 hash와 변경 근거를 보존했다.

### R6 초기 실험 UI

추가 비교 UI: 저장된 feedback-revision-02.json의 ranges를 /api/structure-preview 읽기 전용 개발 API로 불러온다. 오른쪽 'Phrase 묶음 비교'에서 현재 경계/제안 범위를 전환한다. 제안은 사용자가 선호한 범위의 미리보기이며 알고리즘의 최종 자동 선택이 아니다. baseline 데이터와 기존 Motif 분석은 그대로 유지한다. 신규 work별 코드 분기 없이 사례 문서에서 범위를 읽고 현재 note identity를 검증한다.

악보 오른쪽의 '반복 경계 검토 · 실험'에서 평가 스크립트가 생성한 review-ui.json을 불러오고 후보를 선택한다. 저장된 음표 정보와 현재 work가 다르면 거부한다. 기존 Phrase는 유지하며 선택한 원형/재등장만 별도 점선으로 표시한다. 첫 자료는 `evaluation/reports/repeat-review-ui-008-v1/review-ui.json`. 파일 업로드는 브라우저 안에서 읽기만 하며 서버 전송/피드백 저장을 하지 않는다. UI 시각 검증과 전문가 평가 전이며 자동 적용은 없다.

### R3/R5 후속 — 예산 분배와 저장 경계 비교

가변 범위 리뷰 v0.2는 그룹별 한 정렬씩 round-robin으로 실행한다. 정렬 후보가 없는 그룹도 결과에 남기고 각 그룹의 정렬 수와 완료/partial을 기록한다. 이는 입력된 그룹 사이의 분배 개선일 뿐, 상위 seed 탐색의 앞부분 편향이나 그룹 내부 순서를 해결하지 않는다. 예산이 유효 그룹 수보다 작으면 일부 그룹은 여전히 미검토다.

`repeat-boundary-review.mjs`는 후보 생성 후에만 snapshot의 기존 Phrase 경계를 연결한다. 양쪽 event ID 범위와 마디, 내부 경계, 직접 정렬된 attack 위치의 경계 유무 차이, melody/rhythm/coverage를 보존한다. 동일 범위쌍은 중복 제거하지만 서로 다른 범위 대안은 유지한다. 삽입/삭제 gap만 있는 위치를 억지로 경계 대응하지 않는다. 모든 판단은 cannot_judge, autoApply=false이며 저장 당시 baseline이지 실시간 UI 결과가 아니다.

v2 보고서(004/006/008): 정렬500/236/500회, 고유 범위쌍22/33/43개, 경계 차이가 있는 범위쌍1/21/4개. 008의 원형4–12마디와 재등장12–20마디에서 내부 경계0/1 차이를 회수했다. 이는 오류 확정이나 평가 정확도가 아니다. 관련26테스트 통과. 운영 연결·화성 판단·XML rest 검증은 그대로 보류한다. 보고서는 `evaluation/reports/repeat-elastic-{004,006,008}-v2`에 있다.

첫 실행 결과: ALWAYS WITH ME에서 경계 입력 없이0/30 대응과4/34 음가→쉼 치환을 회수했다. 14테스트 통과. 5,639 seed검사 후 정렬300회 예산 소진으로 partial. 겹친 창28개 관찰은 독립 사례 수가 아니다.

### R3 2차 — 준비부와 가변 attack 수의 범위 후보

`server/repeat-elastic-extent.mjs`는 1차 결과와 별도로 `elastic-review.json`을 만든다. 기존 Phrase 경계는 입력하지 않는다.

- 기본 앞3음/뒤4음 범위에서 후보를 검토한다. 대응 양쪽 종결음+뒤 쉼이 각각 기준박1 이상인 후보끼리 비교하며 attack 수가 달라도 동적 정렬한다. 첫 음/끝 음과 최초 검색 anchor가 모두 직접 대응해야 한다.
- 준비부는 양쪽에 대응 음이 있어야 한다. anchor의 조옮김 대비 pitch residual 2반음 이내, anchor까지의 상대 시간과 음가 비율을 별도로 검사한다. 전체 core 점수가 높아도 준비부 자체가 맞지 않으면 붙이지 않는다. 이는 준비음의 음악적 기능 확정이 아니라 선행 대응 후보이다.
- 내부의 긴 쉼/호흡표기는 보호한다. 미지원·변경 박자와 문맥 부족은 보류한다. 원본 tie/rest XML 검증, 악곡 마지막 종결은 아직 미지원이다.
- coverage/melodic/rhythm 각75점 이상을 검토 필터로 사용한다. 미보정 임계값이며 confidence가 아니다. 총500정렬 예산과 partial을 기록한다. 후보 순서에 따른 누락을 해결하기 전 자동 적용하지 않는다.
- 내부 삽입/삭제를 포함한 길이 차이는 지원하지만, 양쪽 준비부의 음표 수가 다른 경우는 보류한다. 반복음을 나눈 것인지 장식음을 추가한 것인지 의미적으로 확정하지 않는다. 음표 분할/합침의 엄격한 리듬 보존 규칙은 R2 후속이다.

저장 사례004/006/008에서 실행했으며 각각 후보12/44/71개를 출력했다(중복 포함, 정확도 아님). 004/008은500정렬에서 partial,006은236정렬로 주어진 범위만 완료했다. 상위 반복 탐색은 세 사례 모두 partial이므로 전체 악곡 검토 완료로 해석하지 않는다. 결과는 `evaluation/reports/repeat-elastic-004-v1`, `repeat-elastic-006-v1`, `repeat-elastic-008-v1`에 보존한다. 다음은 예산 분배와 겹친 대안 정리, XML 증거 대조, 기존 경계와의 리뷰 연결이다. R3는 부분 구현이고 R4–R6 및 운영 경계 변경은 미구현이다.

계획은 이 문서, 구현 기록은 development-log.md, 사용자 의견은 evaluation/cases, 악보는 case-assets, 실행 결과는 evaluation/reports/repeat-first-*에 둔다. 실행 명령: `node scripts/evaluate-repeat-first.mjs S-STRUCT-008 repeat-first-008-v1`. 보고서가 있으면 덮어쓰지 않는다.

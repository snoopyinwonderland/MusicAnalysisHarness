# 검색 평가 재검토와 다구간 차용 탐지 계획

후속: [합성 원곡 4개·변형 입력 24개 제작 완료](copyright-multisegment-fixtures-v1.md). 아래는 초기 계획이며 실제 corpus 검색/법률 판정은 미실행이다.

상태: 설계 제안. 이번 작업은 문서/기록 검토이며 새 XML 생성, 검색 재실행, 판정 코드 변경은 하지 않았다.

## 1. 기존 검색 성과의 해석

- motif-300: Top5 96/100, Top100 99/100. 내부 한 음 옥타브 이동 미회수, 판본/공통 선율 가족에 따른 순위 차이.
- motif-350: Top5 50/50, Top1 39/50. XML/SVG target 검사 포함.
- 후속 preclearance variation50: source 회수 32/50, Top5 30/50. 5 source 중 3개가 ENDLESS LOVE 편성. 단일 반음/두 음 변경/삭제 취약성이 관찰됐으나 기존 세트와 다른 조건이므로 회귀 확정은 아님.
- 누적 사례 수를 현재 단일 버전의 검증 정확도로 사용하지 않는다. 같은 코드·DB·work-family 정답·limit로 기존 suite를 다시 비교해야 한다.
- 우선순위: 원본/판본 family 정답 정리 → 후보 회수 vs admission vs rerank 탈락 원인 분리 → 독립 작품 holdout 및 hard negative → 점수/정렬 설명 → 지연 p95.
- 무조건 하한을 낮추거나 특정 작품을 고정하지 않는다. 새 진단은 분석 보강보다 실패 단계의 증거 확보가 먼저다.

## 2. 검색과 저작권 사전검토를 분리

검색 엔진은 변형에도 원곡 후보를 놓치지 않는 역할을 유지한다.
후단에서 다음 항목을 별도 평가한다.
1. 실제 표현의 대응: 연속 선율, 상대 음고, 리듬/쉼, 구절 순서, 변형 설명.
2. 특징성: 반복음/음계/아르페지오 등 관용구 단독 근거와 특징적인 결합 구분. 낮은 코퍼스 빈도만으로 창작성 확정 금지.
3. 독립 구간: 겹친 창, 같은 프레이즈 반복, 편성/판본 중복을 가족 단위로 병합.
4. 질적 중요도 및 양: 원곡의 주제/후렴 근거와 확신도, 양쪽 작품에서 차지하는 합집합 음표·음가·구간 비율.
5. 권리·사용 사실: 보호 기간/관할/권리자/이용허락/독립 창작·접근 정보/예외 여부. 미상은 미상.
Contour·분위기·일반 리듬형·Schenker-informed 골격 단독 일치로 높은 법률 위험을 결론내리지 않는다.
관용 요소 각각이 흔하다고 그 독창적 결합까지 자동 제거하지도 않는다.

최종 경고는 검토할 음악적 근거를 제시한다. XML 비교만으로 의거·허락·예외·실제 침해를 확정할 수 없다.
출력은 '침해 구간 N개' 대신 '고유 유사 구간 N개 / 총 발생 M곳 / 권리 검토 필요'로 구분한다.
고유 프레이즈 1개가 4번 나오는 것과 서로 다른 4개가 대응하는 것을 분리한다.
복수 독립 구간의 증거는 중요하지만 무조건 개수에 비례하거나 두 구간부터 침해라는 규칙을 만들지 않는다.
단일한 짧은 핵심 구절도 검토할 수 있어 최소 음표/마디 수의 법적 안전선을 만들지 않는다.
현재 70% coverage·70 similarity·beta 0.2는 미보정 휴리스틱이며 법적 경고 기준으로 승격하지 않는다.

## 3. MusicXML 검증 샘플 — 첫 파일럿 24개 제안

권한이 확인된 서로 다른 원곡 4개 × 아래 6유형. 우선 자체 제작·사용 허락된 원본 또는 보호기간이 검증된 작품.
보호기간 만료 원본은 음악적 차용 탐지 양성 대조군이며 '권리 침해 양성' 정답이 아니다.
임의 75년 경과로 권리 자유를 확정하지 않고 편곡 표현과 녹음 권리도 별개로 취급한다.

| 유형 | 파일 내용 | 검증 질문 |
|---|---|---|
| 원본 기준 | 원본 그대로, 격리된 검사 모드 | exact baseline 및 동일 파일 중복 처리 |
| 1구간 | 특징적 프레이즈 하나를 다른 문맥에 삽입·변형 | 한 곳의 출처와 범위를 찾는가 |
| 2구간 | 원곡의 서로 다른 두 프레이즈를 떨어져 배치 | 고유 2개로 집계하는가 |
| 3구간 | 서로 다른 세 프레이즈, 순서/성부 일부 변경 | 전곡 여러 위치의 근거를 모으는가 |
| 반복 대조 | 같은 프레이즈 하나를 세 번 배치 | 고유 1개/발생 3곳으로 구분하는가 |
| hard negative | 같은 박자/조성/관용 음형/윤곽의 독립 문맥, 특징적 구절은 미삽입 | 일반적인 유사성을 과잉 경고하지 않는가 |

음높이 국소 변경, 전조, 전체/국소 옥타브, 리듬 재분배, 쉼·장식음 삽입/삭제를 균형 배치한다.
먼저 한 변형씩, 후속 난도에서 복합 변형으로 확장한다.
주 시험은 **원곡 전체를 조금 변형한 복제본이 아니라 새로운 scaffold에 일부 구절을 넣은 파일**이다.
원곡 전체 변형은 별도 쉬운 sanity test로만 사용한다.
배경과 연결부가 우연히 다른 곡과 일치할 수 있으므로 hard negative도 사람의 확인 전 법적 비침해 정답으로 확정하지 않는다.

생성 시 divisions/tuplet/마디합/backup-forward/쉼/타이/성부/악기/못갖춘마디를 보존 또는 일관되게 다시 구성한다.
원본 덮어쓰기 금지. MusicXML round-trip 재파싱, 이벤트 대응, Verovio 렌더, 청취 검증 후 업로드 검사.
생성 파일은 테스트 입력에만 두고 검색 DB에 넣지 않는다. 후보 DB에는 원본과 실제 비교곡만 존재해야 한다.

## 4. 정답 누출 및 원곡 제외 정책

생성 관계표는 evaluator만 읽으며 검색 엔진과 분석기에는 전달하지 않는다.
파일명/title/composer 등 원곡 힌트도 검색에 사용하지 않으며 blind test 파일명으로 제공한다.
원곡은 검사 후보로 남겨야 한다. 변형 업로드를 원곡 canonical ID에 묶어 self-exclusion 하면 핵심 정답이 사라진다.
동일 업로드 파일 또는 확인된 동일 판본의 중복 제외와, 변형/차용 의심 원곡의 비교를 분리한다.
원본 동일 파일 기준 시험의 정책 결과와 파생 파일의 출처 탐지 결과를 별도로 기록한다.
이것은 특정 정답의 순위를 강제로 올리는 예외가 아니라 업로드 동일성/계보 관계의 일반 계약 변경이다.

## 5. 전곡 검사와 보고서

현재 최대 7 Phrase 선별은 전곡의 여러 차용 구간을 빠짐없이 확인하는 데 충분하지 않다.
빠른 1차 후보 탐색 후 전체 Phrase/window를 검사하되 동일 Query 재사용·배치·중단/재개를 활용한다.
예산으로 일부만 검사했다면 검사 범위/미검사 위치를 표시하고 완전한 결과나 안전 판정으로 쓰지 않는다.
노트 수와 시간 기준 범위, 같은 성부/복수 성부, 파트 이동을 분리한다.
정렬이 다른 voice를 무단 횡단하지 않도록 일관성 검사한다.

보고서 첫 화면:
- 분석 완료/부분 완료, 검사 범위, 권리 정보 확인 상태.
- 원곡 후보별 고유 대응 구간 수, 총 발생 위치, 양쪽 비중, 중요한 대응과 반대 근거.
- 업로드 타임라인의 대응 범위와 원곡 마디를 연결한 지도.
- A/B 악보·합성음·정확 대응/변형 대응/추정 골격의 시각적 구분.
- 결론 예시(가상): '작품 A의 서로 다른 특징적 프레이즈 3개에 대응하는 구간을 발견했습니다. 허락 여부와 권리 상태를 확인하고 전문가 검토를 권고합니다.'
- 탐지 없음은 침해 없음/법적 안전 보장이 아니라 검사 범위 내 강한 근거 미발견.
침해 확률 %나 자동 침해 확정 라벨은 전문가/관할별 검증 없이 사용하지 않는다.

## 6. 평가와 저장

사례 묶음은 독립적으로 내보낼 수 있도록 원본 hash/권한, 원본 XML 문맥, 파생 XML,
이벤트 snapshot, transform seed/recipe, 원본↔파생 note/measure/part/voice/onset mapping,
차용 family/occurrence 정답, 유형, 사용자 설명, 결과, 문제, 개선안, 분석/검색 버전을 보존한다.
공유 금지 자산은 로컬 권한 경로로 분리한다. 기존 musicanote-evaluation-case/v1과 sidecar provenance로 확장하며 기존 사례를 덮어쓰지 않는다.

평가지표:
- canonical 원곡 recall@1/@5, 후보 생성 recall 및 제외 원인.
- 구간 precision/recall, 음표 대응 precision/recall, 경계 오차, window 중복 제거와 family/occurrence 집계 정확도.
- hard-negative 경고율, 중요 구절 미탐, 권리 확인/미확인 표현 정확도.
- 반복 구간/다중 source/motif-only/전곡 일부 미검사 사례.
- 유형·작품별 latency p50/p95, timeout, 검토 범위.
최초 source 4개는 작은 기능 파일럿이며, 임계값 보정용과 최종 holdout은 canonical 작품 단위로 분리한다.
합성 변형 정답은 '이 구간이 이 원곡에서 만들어졌다'는 출처 정답이지 법적 침해 정답이 아니다.
법률·음악 전문가가 평가한 실제 분쟁/허락/독립 창작 대조 사례로 경고 기준을 별도 검증해야 한다.

## 7. 실행 순서

1. 기존 suite를 단일 코드·DB 기준으로 재평가할 manifest와 작품 family 정답 정리.
2. 권한 확인 원곡 선정, 격리된 생성/evaluator 계약, 첫 MusicXML 24개와 렌더 검증.
3. self-exclusion과 전곡 검사 범위 계약 수정, 구간·가족·발생 수 집계 회귀.
4. 음악적 근거/권리 상태를 분리한 리포트 프로토타입.
5. blind 실행, 오탐·미탐 리뷰, 일반 규칙 보완. 같은 작품으로 튜닝과 최종 평가를 동시에 하지 않는다.

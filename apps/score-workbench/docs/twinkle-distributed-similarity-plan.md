# Twinkle–Ma Boy 회수를 위한 일반 검색 개선 계획

상태: 계획. 이 문서 작성으로 검색 논리를 변경하거나 추가 검색을 실행한 것은 아니다.

## 1차 목표와 완료 기준

Twinkle 전체 파일을 입력했을 때 현재 전체 검색 DB에서 Ma Boy를 자동 회수하고, 리포트의 검토 대상에 제시한다. 작품명·특정 마디·정답 ID에 따른 후보 주입이나 가산점은 금지한다. Ma Boy만 지정한 비교는 진단용이며 목표 달성으로 집계하지 않는다.

- 1차 통과: 기본 리포트 표시 범위인 상위 10개 검토 후보 안에 Ma Boy가 나타나고, 입력/비교곡 양쪽의 실제 대응 구간, 음표·음가·변형 근거를 악보와 재생으로 확인할 수 있다. 1위 강제는 하지 않는다.
- 후속 통과: 서로 다른 구절에서의 변형 유사성이 실제로 확인되면 구간별로 보여주고, 같은 구절 반복과 독립된 구절 수를 분리한다. 최소 구간 수를 맞추려고 약한 일치를 덧붙이지 않는다.
- 오탐 확인: 흔한 음형/같은 리듬/단순 반복만 비슷한 대조군과 다른 실곡 사례에도 동일 규칙을 적용한다. 기존 변형 Query 회수율과 지연의 전후 차이를 함께 기록한다.
- 음악적 근거가 부족하면 점수를 억지로 맞추지 않고 부족한 근거와 실패 단계를 보고한다. 이 회수 목표는 법적 침해 확정 목표가 아니다.

## 현재 기준선

`evaluation/reports/real-pairs-existing-v1/` 보존 결과:

- Twinkle: 한 성부의 7개 Phrase 검색 완료. Ma Boy 미회수. 439개 attack 중 직접 검색 175개, 반복 대표 포함 329개. 14–15마디도 검색되었지만 해당 Query의 반환 결과 30개에 Ma Boy가 없다.
- When Love Takes Over: 7개 검색 완료, Clocks 미회수.
- Jesus of Suburbia: 준비 도구가 변박을 단일 unknown 값으로 전달하여 Query 0개, 검색 미실행.
- 21 Guns/Telephone Line, Johnny B. Goode/Ain't That Just Like a Woman: 참조곡을 기존 영문 제목 조회에서 찾지 못해 이번 기준선에서는 미실행. DB 전체 부재 확정은 아니다.

## 단계 1 — 입력과 대응 좌표 감사

Twinkle 입력, 제공 Ma Boy XML, DB Ma Boy KY 76909의 성부·음높이·실음/기보음·옥타브·타이·쉼·박자·마디 좌표를 대조한다. 제공 XML과 KY 판본을 같은 이벤트 배열이라고 가정하지 않는다. 자동 선택한 성부에 실제 보컬 선율이 있는지 확인한다. 주요 비교 구간 전후 문맥도 보존한다.

동시에 일반 준비 도구에 마디별 박자/ordinal을 보존할 방법을 점검한다. Jesus of Suburbia를 임의 4/4로 처리하지 않고, 변박을 넘지 않는 구절의 실제 박자부터 전달한다. 여러 성부가 있는 입력은 성부별 후보를 만들되 하나의 선율로 섞지 않는다.

산출물: 원본 해시, parser 버전, 성부 목록, 이벤트 ID와 XML 마디/ordinal 매핑, 미지원 사항, 재현 가능한 문맥 파일.

## 단계 2 — Ma Boy가 사라지는 단계 추적

기존 7개 Query와 전체 DB를 그대로 재실행하며 후보 생성 → 창 선택 → 정렬 → 결과 허용/거절 → 순위 → 반환 상한 → 작품 집계 → 리포트 표시를 계측한다. 평가기는 Ma Boy ID로 로그를 읽을 수 있지만 검색기는 그 ID로 후보나 순위를 바꾸지 않는다. 자기 일치도 가능한 한 검색 반환 뒤가 아니라 후보 생성 전에 확인된 동일 작품 ID로 제외한다.

별도 진단에서 같은 Query를 Ma Boy 스트림에 직접 정렬해 후보 생성 문제와 비교 점수 문제를 분리한다. 이 결과에는 반드시 '비교 대상 지정 진단; 전체 DB 회수 성과 아님' 라벨을 붙인다.

산출물: 각 Query의 단계별 생존 여부, 거절 사유·측정값·임계값, 반환 전 순위, 처리 시간. 원인이 밝혀지기 전 전역 허용 임계값을 낮추지 않는다.

## 단계 3 — 원인에 맞춘 구간 탐색과 정렬 개선

다음은 실험 후보이며 전부 기본 적용하는 계획은 아니다.

1. 관련 구절을 놓치면: 대표 7개 한정에서 벗어나 Phrase 가족 전체를 순차 검사한다. 불확실한 경계에는 제한된 겹침 창/부분 Phrase를 추가한다. 검사 예산과 미검사 구간을 노출한다.
2. 인덱스에서 놓치면: 음정·음형·리듬형 등 보완적인 seed를 합쳐 후보 회수를 확장하되 최종 비교 기준은 별도로 유지한다. seed 종류와 실제 회수 기여를 기록한다.
3. 정렬에서 놓치면: 한 음의 치환이 앞뒤 두 interval 오차로 중복 과벌되는지 확인한다. 단일 조옮김 오프셋을 유지하는 음표 단위 정렬과 기존 interval 근거를 비교한다. 음마다 자유로운 조옮김/옥타브 변경으로 억지 일치를 만들지 않는다.
4. 구절 길이가 다르면: 삽입·생략 비용과 시간적 연속성을 함께 평가한다. 짧은 약박 보조음은 제한적으로 가볍게 처리하되, 임의로 띄엄띄엄 음표를 고르는 경로는 억제한다.
5. 중요음 비교: 각 곡의 문맥에서 독립 추출한 기둥음 후보와 박자 위치를 사용한다. 상대 곡에 맞춰 기둥을 사후 선택하지 않는다. 휴리스틱과 확정된 사람 분석을 구분한다.

산출물: 한 번에 한 가지 변경의 A/B 결과. 개선되지 않거나 오탐이 증가한 변경은 보류한다. 일반 검색과 저작권 검토의 후보 회수/최종 검토 기준 차이는 명시한다.

## 단계 4 — 분산된 유사 구절의 작품 단위 집계

개별 창을 먼저 충분히 검증한 뒤, 같은 비교곡에서 잡힌 구간들을 작품 단위로 모은다. 입력/비교 양쪽에서 겹친 구간은 묶고, 같은 구절의 반복은 가족별 횟수로 표시한다. 서로 다른 특징적 구절의 일치는 별도 근거로 남긴다.

최고 구간 점수, 독립 Phrase 가족 수, 양쪽에서 겹침을 뺀 음표/음가 비중, 변형 유형, 문맥 중요도, 코퍼스에서의 흔함을 분리 표시한다. 모든 약한 점수를 단순 합산하거나 두 구간을 무조건 두 배로 계산하지 않는다. 반복은 기여가 포화되도록 하고, 관용 음형만 여러 개 모인 경우에는 경고 수준을 제한하는 방식을 대조군으로 검증한다. 집계 계수는 이 계획에서 임의 확정하지 않는다.

산출물: 입력/비교곡 구간 지도, 구간별 비교 악보·재생, 반복/독립 구절 구분, 작품 검토 순위의 설명. 검색 자체 점수와 작품 단위 검토 순위를 구분한다.

## 단계 5 — 다른 실곡과 대조군 검증

검사 순서: Twinkle → When Love Takes Over → Jesus of Suburbia → 21 Guns → Johnny B. Goode.

- Clocks: 보컬 외 피아노/반주 음형의 회수 여부를 확인한다. 선율 스트림만 검사해서 놓친 경우와 비슷한 반주 관용형을 과대 평가한 경우를 구분한다.
- Summer of '69: 변박 입력 문제를 먼저 해결하고 긴 곡의 부분 구간이 선별에서 누락되지 않는지 확인한다.
- Telephone Line, Ain't That Just Like a Woman: 참조 판본의 존재를 재확인하고, 없으면 제공 참조 XML을 비공개 평가용 보조 인덱스에 추가한다. 작은 비교 DB 결과와 전체 corpus+보조 인덱스 결과를 혼합하지 않는다. 입력곡을 정답 참조로 다시 색인하지 않는다.
- 양성 후보는 공개 비교/사용자 관찰에 근거한 음악적 유사성 가설이지 법적 정답이 아니다. 청취·악보 확인 후 근거 강도를 기록한다.
- 반복음·상행 음계·흔한 분산화음·같은 리듬만 공유하는 대조군을 준비한다. 일부 대조군은 수정 중 보지 않는 검증 세트로 남긴다. 기존 400개 테스트의 가능한 동일 조건 회귀도 수행한다.

산출물: 회수율, 후보 단계 recall, 참조곡 순위, 전문가 검토 대기/확인/반려 구간, 구간 위치 정확도, 오탐, 지연. 서로 다른 실행 조건의 점수를 하나의 성공률로 합치지 않는다.

## 기록과 실행 순서

### 공개 주석 47·48 검토 보완

[48번](https://musicanote.com/score/detail/508?annotation_id=48)은 Twinkle 14–15 대 Ma Boy 10–11, Twinkle 15–16 대 Ma Boy 12의 선율/음형 관계를 주장한다. [47번](https://musicanote.com/score/detail/508?annotation_id=47)은 도입부, 화성 진행, 리듬형과 가사 배치의 관계를 주장한다. 공개 본문 두 건을 읽었으며 악보·음원 대조로 검증된 사실과는 구분한다. 출처·좌표·상태는 `evaluation/real-cases/five-pairs/twinkle-annotation-observations.json`에 저장했다.

적용할 검증 규칙:

- 서로 길이가 다른 구간과 Phrase 경계를 넘는 대응도 제한된 부분 정렬로 평가한다. 마디 수가 다르다는 이유만으로 배제하지 않되, 건너뛴 음과 시간 확장을 증거에 표시한다.
- 48번의 두 관찰은 입력 15마디를 공유한다. 겹친 이벤트를 합집합으로 계산하며 독립 구절 두 개로 자동 인정하지 않는다.
- 화성은 조성 기준 근음 도수, 화음 성질, 실제 베이스, 지속시간, 반복 위치를 분리한다. 글의 4–3–6–5–1을 일반적인 다층 특징의 예로 사용할 수 있지만 이 진행을 특별 우대하지 않는다. III의 m7/7 차이는 삭제하지 않으며 원본 조성과 기능을 먼저 확인한다.
- 도입부/프레이즈 안의 상대 위치와 선율·리듬·반주의 동시 대응은 후속 복합 근거이다. 흔한 진행과 단순 음형은 코퍼스 빈도 및 대조군으로 과대 집계를 방지한다. 상관된 특징을 독립 증거처럼 단순 합산하지 않는다.
- 가사 배치는 선택적 보조 검토로 보류한다. XML 가사 존재, 음절-음표 연결, 흔한 문구 여부가 확인되지 않으면 점수에 넣지 않는다.

현재 `server/preclearance-musical-evidence.mjs`의 contour/figures/skeleton은 반환 후보의 보조 비교이고 skeleton은 `harmonyAssessed:false`이다. 이 레이어만 강화해서 후보 단계의 미회수를 해결했다고 말할 수 없다. 순서는 기존 단계 1·2의 좌표 감사/탈락 진단 → 48번 유형의 부분 변형 회수 A/B → 필요한 경우 화성·배치 보조 근거 추가로 유지한다. 알려진 주석 마디로 직접 비교하는 결과는 지정 진단이며 전체 DB 자동 회수와 별도로 기록한다.

이번 보완은 분석·계획 기록이며 검색 점수나 후보를 변경하지 않았다.

실행마다 새 디렉터리에 입력/참조 해시, parser/analyzer/search 코드 버전과 설정, DB 지문, Query(쉼표 포함), 반환 전후 순위, 탈락 사유, 정렬 경로, 문맥 악보, 사용자 관찰과 수정 가설, A/B 결과를 연결한다. 기존 결과는 덮어쓰지 않는다. 사람이 부여한 평가와 자동 산출값은 분리한다.

바로 다음 작업은 **단계 1의 Twinkle/Ma Boy 데이터 감사와 단계 2의 탈락 추적**이다. 이 진단 결과를 근거로 단계 3의 필요한 실험만 선택한다. Twinkle 단독 성공만으로 배포하지 않고 단계 5의 다른 사례와 오탐 검증을 통과시킨다.

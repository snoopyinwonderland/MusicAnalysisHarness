# 향후 Query 선별과 박자 검증 우선순위

2026-09-17 사용자 의견: 12음 전체 단순 순차진행은 실사용 수요가 작으므로 핵심 성공 사례로 과도하게 다루지 않는다.

- 앞으로 주 평가용 원형은 전체 단방향 순차진행/전체 동음반복을 제외한다. 원곡 전체가 아니라 선택한 12음·8음 등의 각 Query에 적용한다. 짧은 순차·반복 구간이 섞인 특징적인 선율은 제외하지 않는다.
- 기존 Query·응답·통계는 삭제하거나 소급 변경하지 않는다. EM09 같은 단순 패턴은 별도 스트레스 사례로 보존하고 향후 주 평가 성공률에서 분리한다.
- 새 선별기는 evaluation/query-selection-policy.json 기준을 읽고 검색 전에 선별해야 한다. 기존 역사적 생성기를 소급 변경하여 과거 suite를 다른 표본으로 재생성하지 않는다.

## 박자별 계획 (아직 실행 승인/실행 아님)

1. 2/4: 새 특징적 원형 5개 × 원형/장식음 삭제/음가 흡수 = 15회 소규모 검증 권장. 4/4와 많은 연산은 같지만 마디당 downbeat 간격(2박 대 4박), 4/4의 3박 부강세(.65)와 2/4의 새 마디 첫박(1)이 다르다. 마디 경계·못갖춘마디·쉼표 전후를 포함한다. 60~100회 확장은 우선 불필요.
2. 5/8·7/8: 대량 실제 검색보다 박 묶음 계약 검증이 먼저. 현재 production metricWeightAt은 5/8=2+3, 7/8=2+2+3으로 고정하며 source-only structural-reduction은 grouping이 없으면 unknown(null) 처리한다. 두 계층의 정책도 다르다.
3. 5/8의 3+2, 7/8의 3+2+2/2+3+2를 현재 코드가 자동으로 구별한다고 주장할 수 없다. 또 5/8은 frontend Meter 및 붙여넣기 검증 목록에 없다. 이 지원을 정리한 후 각 grouping별 소수 회귀로 검증하고 실제 서비스 수요에 따라 확대한다.

음계 원형 누락의 원인 기록(EVAL-007)은 보존하되 해당 베토벤 작품을 반드시 상위에 올리는 별도 최적화는 우선하지 않는다. 새 대량 테스트 대신 기존 미반영 8개 개선 주제를 정리하는 쪽이 다음 우선순위다.

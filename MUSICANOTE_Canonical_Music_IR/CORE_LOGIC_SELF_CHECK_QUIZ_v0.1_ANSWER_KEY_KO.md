# MUSICANOTE 핵심 논리 이해·합의 점검 퀴즈 v0.1 — 정답과 해설

퀴즈를 먼저 푼 뒤 확인한다. 이 정답은 현재 v0.1/v1.2 설계와의 일치도를 뜻하며, 사용자의 음악적 견해가 틀렸다는 의미는 아니다.

## 객관 문항

1. **B** — 동시 onset과 pitch spelling은 관찰 사실이다. `I`는 조성과 문맥이 필요한 해석이다.
2. **C** — 기보 단위, 지속되는 소리, 새 attack을 분리해야 화성·리듬·검색에서 tie continuation을 새 음으로 오인하지 않는다.
3. **A** — 모든 범위는 start 포함, end 제외인 `[start,end)`를 사용한다.
4. **D** — 조표는 관찰 사실이고 global/local key는 분석 가설이다.
5. **B** — enharmonic spelling은 기능화성, 해결 방향과 성부진행의 증거다.
6. **C** — metric strength는 재계산 가능한 증거이며 NCT 유형은 문맥적 해석이다.
7. **B** — 현재 기본 span은 음표를 공유하지 않는다.
8. **C** — `P1│P2`는 공유 membership을 암시하므로 보통 경계에는 부정확하다.
9. **B** — overlap은 별도의 명시적이고 versioned된 해석이어야 한다.
10. **C** — 내부 articulation은 버리지 않고 계층을 낮춰 보존한다.
11. **C** — Phrase 5라는 번호나 특정 pitch가 아니라 정규화 리듬과 상대적인 closing gap의 결합이다.
12. **B** — 뒤쪽 closure가 충분히 크지 않으면 현재 좁은 merge rule은 발동하지 않는다.
13. **C** — 반복 계속성과 강한 종지는 서로 경쟁 가능한 분석 증거다. 둘 중 하나를 지우지 않는다.
14. **B** — 가사는 weak supervision의 위치 단서이지 운영 분석의 필수 feature가 아니다.
15. **B** — 관찰된 불완전 sonority와 분석 불확실성을 그대로 표시한다.
16. **C** — AI와 사람의 판단을 분리 보존해야 모델 교체, 재학습과 감사가 가능하다.

## 점수 해석

- 14–16개 일치: 현재 아키텍처와 높은 합의
- 11–13개 일치: 핵심은 대체로 합의, 일부 용어·계층 재확인 필요
- 8–10개 일치: 음악적 판단과 데이터 계약이 섞이는 지점을 함께 검토할 필요
- 0–7개 일치: 구현을 더 진행하기 전에 Core/Evidence/Analysis/Annotation 경계를 다시 합의하는 편이 안전함

점수보다 확신도가 중요하다. `낮은 확신으로 맞힌 문항`은 문서나 UI 설명을 개선할 후보이고, `높은 확신으로 다르게 답한 문항`은 실제 설계 충돌 후보이다.

## 17–20번 검토 기준

정답을 고정하지 않는다. 답변에서 다음을 추출한다.

- 경계의 긍정 증거와 계속성의 반증 중 어느 쪽을 우선하는가
- authentic/half cadence가 반복 구조를 어느 강도에서 중단시킬 수 있는가
- phrase와 subphrase를 배타적 분할로 보는가, 중첩 계층으로 보는가
- overlap을 청각적 재해석으로 보는가, 동일 attack의 실제 이중 membership으로 보는가
- UI correction을 단순 label 수정으로 볼지 competing hypothesis 생성으로 볼지

답변을 다음 개발 산출물로 변환할 때는 원문 판단, 적용 조건, 예외, 반례, 필요한 evidence와 confidence를 함께 기록한다. 한 작품의 마디·음높이·ID를 일반 규칙에 직접 넣지 않는다.

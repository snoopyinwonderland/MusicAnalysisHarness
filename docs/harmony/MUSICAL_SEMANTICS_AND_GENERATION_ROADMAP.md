# 음악적 의미·배치·전개와 작곡/편곡 로드맵

정본 진입점은 [화성 개발 메인 문서](README.md)다. 이 문서는 화성 결과를 **실제 음표 배치와 음악 전개**에 이용하기 위한 데이터 계약·실행 순서다. 현재 화성 추론의 완료 선언이나 인수인계 문서가 아니다. 최초 작성: 2026-10-01.

2026-10-01 사용자 요청으로, 분석 도구를 단조롭지 않은 네 편성의 편곡과 모티프/프레이즈 기반 작곡에 연결하는 대화 내용을 [§10 활용 기획](#composition-arrangement-application-plan)에 보존했다. 이 추가는 개발 기획 문서화이며 생성기 구현·학습·편곡 성능 검증 완료가 아니다.

## 1. 사용자 목표와 이번 구현 경계

사용자는 단선율에서 복잡한 피아노 솔로, 듀엣·트리오·쿼텟을 만들고, 더 나아가 교향곡 규모의 작곡과 '인공 지능 모차르트'를 지향한다. 음표/음군/모티프가 어떤 역할을 하고 무엇이 먼저/뒤에 오는지에 대한 실마리를 지금부터 저장하고, 이전 사례에도 이후 같은 정보를 추가하도록 요청했다.

개발자는 이를 다음처럼 구체화한다.

- 화음 기호를 아는 것과 반주·대선율·성부를 실제로 실현하는 것은 별도 기능이다.
- 복잡함은 무조건 음표 수를 늘리는 것이 아니다. 선율 가독성, 독립 성부, 반주 질감, 반복 변형과 대비, 종결의 설득력으로 평가한다.
- 작곡가 이름만으로 스타일을 확정하거나 최종 음악성을 보장하지 않는다. '모차르트'는 장기 스타일·형식·전개 목표이며 지금 검증된 성능 이름이 아니다.
- 이번에는 **선택적 의미 레코드, 원문 수집, 이전 사례의 보충 대기열**을 구현한다. 실제 화성 최종 선택, 음악적 역할 자동 확정, 반주 생성이나 악보 화면 적용은 하지 않는다.
- 새 의미 레이어를 이유로 기존 화성 진행·조성·적용화음·종지 검증 순서를 폐기하지 않는다. 데이터 계약과 수집을 병행하고, 생성 실현은 근거와 평가가 준비된 범위에서 진행한다.

## 2. 네 자료를 혼동하지 않는다

| 자료 | 의미 | 허용된 사용 |
|---|---|---|
| Canonical Core | 원음·음가·철자·part/staff/voice·tie·시간 | 재현과 관찰 계산; 역할/의도는 확정하지 않음 |
| 원주석 | 누가 원자료에서 무엇이라고 기술했는지 | 출처를 가진 해석; 정확한 대상/사용 권한은 별도 검증 |
| 의미 해석 후보 | 규칙/AI/사람이 어떤 역할이라고 판단했는지 | 근거·반례·대안·가정별 비교; 원주석과 분리 |
| 생성 계획/실현 | 어떤 역할을 어디에, 어떻게 배치할지 | 요청/제약과 연결한 새 score revision; 원음 위조 금지 |

같은 음이 앞 화음의 구성음이었다가 뒤 화음에서는 계류나 페달 후보가 될 수 있다. 하나의 tie chain을 하나의 영구 역할로 고정하지 않는다. 기보 `<chord/>` membership은 harmonic chord tone이 아니다. 피아노 sustain pedal과 화성적 pedal point도 별도 개념이다.

## 3. 저장할 의미 축

다음 축은 서로 독립이다. 피아노 왼손=베이스, 최상음=선율처럼 위치만으로 역할을 확정하지 않는다.

| 축 | 질문/후보 | 필요한 연결 |
|---|---|---|
| 성부 역할 | 선율, 베이스, 내성, 대선율, doubling, fill, 응답 | 실제 note/sounding refs, 성부 연결 가정과 전환 구간 |
| 화성 역할 | 근음/3음/5음/7음, 경과/보조/선행/계류, 페달 | 선택/경쟁 화성 refs, 준비·해결, 정확한 시간 |
| 질감·반주 | 분산/블록/알베르티/지속/오스티나토 등 | 음표 순서·음가·박자 상대 슬롯·보이싱·bass pulse |
| 모티프 | 원형, 등장, 변형, core/complete extent | 반복 대응, 가족·variant, 리듬/음정/contour 근거 |
| 형식 역할 | 제시, 지속, 전환, 종결, 회상 등 | 상위 phrase/section, 화성·종지·반복 근거 |
| 전개 관계 | 반복, 이조, 리듬 변형, 연장, 축약, 분절, 응답 | 원형과 변형의 대응표; 삭제/추가/변경 음표 |
| 배치 관계 | 앞뒤 순서, 중첩, 교대, 동시 진행, 대조 | 대상 span/role lane과 상위 계획; 관찰/의도 구분 |
| 표현·연주 | articulation/dynamics, 음역·기법·난이도 | 기보 관찰과 연주 추정 분리; 악기별 profile |

표의 용어는 설계 범위다. 코드에 등록된 어휘와 schema version만 사용하며, 자유문에 단어가 등장했다는 이유로 해당 음표 역할을 자동 확정하지 않는다. 불확실한 설명은 원문을 유지하고 구조화 대기 상태로 둔다.

## 4. 실마리를 실제로 쓸 수 있는 형태

예를 들어 '페달 위의 분산화음'이라는 문장만으로는 생성할 수 없다. 이후 검증된 Pattern Record에는 다음이 필요하다.

1. 원악보/판본/IR revision/hash와 source span, 앞뒤 준비·해결 문맥.
2. 선율·베이스·내성 lane별 rational onset/duration와 원 spelling.
3. 화음 상대 음도와 octave/register; non-chord ornament는 별도 슬롯과 조건.
4. 박자 단위와 패턴 길이. 박자에 대한 비율과 quarter 단위 좌표를 함께 선언.
5. 화음 유형 적용 범위, 필수음·중복/생략·tie across harmony 처리.
6. 음역·손/성부 도약·동시음 폭·템포와 연주 profile.
7. 시작/지속/종결 변형과 어느 구조 위치에서 쓰였는지.
8. 사람 확인 상태·대안·출처/권리/split; 자동 캡션은 원작자의 의도가 아님.

패턴의 첫 **literal observation schema**는 [G1 좌표·음표 단계](records/2026-10-01-native-semantic-alignment-and-pattern-observations.md)에서 구현했다. 명시적27구간의 원음표/음가와 앞뒤 문맥을 보존하며 역할·화음 상대 음도·연주 제약·반주 템플릿은 아직 채우지 않았다. Pattern realizer는 후속이고 원문/음표 수집을 생성에 곧바로 공급하지 않는다.

모티프 전개도 '변형'이라는 이름 하나로 끝내지 않는다. 어떤 음을 유지·이조·분할·연장했는지, core와 완결 구간, 다음 구절의 준비와 종결 목표를 연결한다. 동일 리듬의 여러 기능, 같은 모티프의 다른 종결을 허용한다.

계산 공유와 다양한 실제 change 문맥 검증은 [작품군별 batch 개발 기록](records/2026-10-01-functional-sharing-and-family-batch.md)에 별도로 관리한다. 전체322context/1,013raw lane catalog와 다섯 collection의 고정첫context 선택을 구별하고, 모든 후보·음표·group·원source gate를 유지한다. 전체Python2,940검사와5context/15lane/16group의실제실행은오류0으로완료했다. 기능조건부형태55·해결조건부형태30/30joint_possible를발견했지만화성정답이나cadence완료·음표/작품의독립정답수가아니다.317context/998lane는아직미실행이다. 저장 결과가 같은 계산의 복사를 줄이는 개선은 의미 정확도나 생성 승인으로 세지 않는다. 확대 실행에서도 조건부 기능·해결·박절/NCT 전제와 보류를 저장하며, 역할·반주 템플릿·사용 정책의 G1 심사는 자동 승격하지 않는다.

전후 근거의 후속 구현은 [전후 관측 문맥과 조건부 종지 전제](records/2026-10-01-context-and-cadence-prerequisites.md)에서 관리한다. 창 밖의 원음·타이·시간상 이웃과, 기존 화음/조성 가정 아래 최저·최고음의 구성음·전위·음도·종결 release를 구별해 저장한다. 신규 83개/전체 Python 3,023개 검사와 고정 5문맥의 실제 추가 계산·원자료 보존·독립 fresh replay를 통과했다. 기존 9 bundle 아래 2,195개 가정 조합의 전제를 저장한 것이며 음악 정답·종지 확정 수가 아니다. 전체 명시 path×key를 같은 completion 아래 대조하며, 아직 진짜 선율/구조 베이스·프레이즈 종결·종지나 생성 역할로 승인하지 않는다. 원 short-window 결과나 Core 의미를 변경하지 않는 연구용 추가 레이어다.

## 5. 신규 수집과 이전 사례 보충

앞뒤 문맥을 실제 분석 단위로 새로 정의하는 [확장 scope 공동 가정](records/2026-10-01-expanded-scope-joint-hypotheses.md)을 추가했다. 원 case/path/key/bundle은 보존하고 새 원음·성부·모든 후보와 조표 가정을 분리한다. 전체 Python 3,103검사와 실제 5문맥 계산은 통과했지만, 113group 중 110은 조합 한도 보류이며 실제 비교는 두 full-hold에 한정된다. 이 결과를 바로 반주·성부 배치의 정답이나 생성 템플릿으로 사용하지 않는다. 다음에는 모든 후보의 공유형 비교를 먼저 준비하고, 실제 변화 진행의 분산형·장식·지속 역할과 앞뒤 배치 근거를 연결한다. 원 source/annotation의 해석·학습 자격 및 G1 심사는 그대로 유지한다.

그 후속 [진행 색인과 필요 시 공동 비교](records/2026-10-01-indexed-hypothesis-universe.md)는 원 후보 22,969개와 1,068,810개 논리 진행을 보존한 채 조합 객체 생성 한도를 우회한다. 실제 5문맥의 224개 명시 기술 질의와 각 문맥의 하나의 실제 control bundle 아래 비교만 계산했다. 색인 준비와 최종 화성/장식/반주 역할 판단은 다르며, 전체 논리 조합을 모두 평가하거나 이끎음·7음 해결의 음악적 양성을 확보한 단계가 아니다. 앞/뒤 배치나 생성 템플릿에는 미선택 후보·실제 source refs·대안·보류를 이어받되 의미를 확정해 사용하지 않는다. 다음에는 source shape/target 호환을 공유 계산으로 대조하고 실제 분산형·지연 해결·조건부 역할의 공동 근거를 연결한다.

### 신규 수집

- 원주석의 설명/형식/페달 등의 문장을 누락하지 않고 원문·파일 hash·물리적 줄·주변 문맥으로 보존한다.
- 원자료의 `Note`/`Form`/`Pedal` 태그는 **태그의 출처 분류**다. 음악적 역할의 확정이나 정확한 음표 정렬 인증이 아니다.
- `Note`는 여러 축을 언급하거나 음악 분석이 아닌 편집 메모일 수도 있다. 키워드만으로 역할을 분류하지 않는다.
- 앞/뒤 `m` 줄은 문맥 단서이지 target이 아니다. 원문에 위치가 있어도 반복 엔딩·beat 단위·판본 대응을 확인한 뒤 bound claim을 만든다.
- 아직 정렬되지 않은 원주석은 `needs_alignment`; 사람 확인 없는 자동 가설은 `pending_review`; 처리하지 않은 축은 `not_assessed`다.

### 이전 사례

- 기존 XML/IR/주석/실험 artifact를 수정하지 않는다. case ID와 immutable source hash를 가진 **sidecar**를 추가한다.
- 새 계약의 정보가 없다는 것은 음악적 역할의 부재가 아니다. 기존 조건부 NCT·bass·화성 근거도 삭제하거나 재분류하지 않는다.
- coverage는 축별/대상 범위별로 계산한다. 일부 원문을 받았거나 하나의 음군을 설명한 것은 전체 악보 완료가 아니다.
- 새 레코드는 기존 판본/IR과 정확히 연결되어야 한다. 판본이나 hash가 바뀌면 검증되지 않은 이전 정렬을 재사용하지 않는다.
- 변경은 새 revision과 `supersedes` 계보로 보존한다. 재실행은 같은 입력에 같은 대기열을 만들고 기존 교정을 덮어쓰지 않는다.
- 수집→정렬→구조화 후보→검수→사용 목적별 적격성 심사의 단계로 보충한다. 아직 자동으로 과거 전곡을 재분석/채운 기능은 아니다.

가장 먼저 준비된 source/IR과 사용 정책을 가진 사례부터 보충한다. 평가 holdout은 후속 retrieval/training에 섞지 않는다. 같은 작품의 판본·이조·반복 구간은 독립 작품 수로 세지 않는다.

## 6. 생성 목표의 단계별 완료 기준

| 단계 | 목표 | 다음 단계로 넘어갈 확인 사항 |
|---|---|---|
| G0 — 의미 데이터 기반 | 이번 계약/수집/보충 계획 | 출처·hash·미검토 상태·계보 보존, 원자료 불변, 기존 사례 누락 탐지 |
| G1 — 검증된 패턴과 역할 | 실제 악보의 역할·질감·전개 사례 | 음표 정렬, 재현 가능한 슬롯, 일반 조건/반례, 사용 정책·split 확인 |
| G2 — 피아노 소규모 MVP | 단선율→8–16마디의 선율+베이스+내성+반주 | 선율 보존, 반주 존재/요청 일치, 손별 연주성, 화성 가정 공개, XML 재파싱 일치 |
| G3 — 전곡 피아노 솔로 | 풍부한 피아노 편곡과 구조적 대비 | 전곡 역할/질감/밀도 배치, 반복변형, 종지/전환, 과도 장식·선율 가림 제어 |
| G4 — 듀엣·트리오·쿼텟 | 2/3/4명 편성에 맞는 독립 성부 | 역할 분담·교대·대선율/중복의 구별, 악기 음역·호흡·기법, 총보/파트보 일치 |

G2는 첫 실현 시험이지 사용자의 최소 목표를 8마디로 축소한 것이 아니다. 최소 지향 범위는 G3/G4이며 G5/G6는 더 높은 목표다. 악기 수를 늘리거나 피아노 성부를 다른 악기에 복사했다고 G4/G5를 완료 처리하지 않는다. 교향곡 총보를 파일로 출력하는 것과 교향곡 수준의 음악적 구성도 구별한다.

## 7. 실행 순서와 의존 관계

후속 [같은 성부 가정의 음악적 의미 공동 비교](records/2026-10-01-factor-conditioned-musical-meaning.md)는 factor geometry를 경과/보조·선행·분산 구성음·지속 베이스 형태 및 원음표/음가/타이/상대 슬롯에 연결한다. 하나의 completion으로 모든 경쟁 path를 대조하고 서로 다른 witness의 설명량을 합치지 않는다. 연구용 구현·전체 2,806 코드 검사·19작품군 33파일 322구간 1,013lane의 고정 자료 r1과 독립 감사를 완료했다. 원자료/음가/원상태가 보존됐고 942unit 처리/71geometry 보류, 실제 170구간 450unit의 754group×lane 비교와 4,222group 보류를 구별한다. 조건부 설명 3,520accounts/62구간 89unit은 음악 정답/역할 선택·슬롯 실현·G1 전체 완료/반주 생성 승인이 아니다. 조성/기능/종지·박절/협화 전제가 불명인 축은 별도로 보류한다. 실제 집계와 개발 실패/정정은 상세 기록을 정본으로 삼는다.

## 10. 분석 도구를 풍부한 편곡과 모티프 기반 작곡에 연결하는 기획 — 2026-10-01

### 10.1 사용자 요구와 현재 능력의 구별

사용자는 이전에 간단한 선율 중심 피아노 악보와 피아노 솔로, 피아노+바이올린 이중주, 피아노+바이올린+첼로 삼중주, 피아노+바이올린+비올라+첼로 사중주의 XML 예제를 제공하여 새 선율의 네 편성 편곡을 시도했으나 결과가 대체로 단조로웠다고 설명했다. 입력을 '단선율'이라고 부르지만 낮은 음자리표에 마디별 화음이 있는 경우도 있으므로 엄밀한 monophonic 입력으로 가정하지 않는다. 앞으로는 모티프 또는 프레이즈 하나만 주어도 완성된 작품을 만들기를 원한다. 이어서 이전 XML들이 `K:/Music Analysis/MusicXML`에 많이 있다고 알렸으며, 이번 답변을 나중의 작곡·편곡 개발 자료로 보존하도록 요청했다.

판단: 현재 분석 도구는 작품을 읽고, 출처 있는 사례와 경쟁 해석을 제공하며, 생성 결과를 점검하는 기반으로 활용할 수 있다. 그러나 그 자체가 완성된 작곡·편곡기는 아니다. Canonical IR/원자료·주석 연결, 성부·화성·조건부 NCT 및 pattern observation의 연구 계층과, 실제 음표를 만드는 **전개 계획기·역할/질감 배치기·악기별 음표 실현기**를 구별한다. 최근의 코드 회귀·보존 검사 통과를 음악적 품질이나 생성 능력의 검증으로 바꾸지 않는다.

이전 생성기 코드는 이번 대화에서 검사하지 않았다. 따라서 단조로움의 원인은 확정 진단이 아니라 다음 개발 가설이다.

- XML의 편성·기보 형식은 모방하지만 음표/성부의 역할과 반주의 작동 원리를 충분히 표현하지 못했을 가능성.
- 구절의 시작·중간·종결을 구별하지 않고 같은 반주·음역·밀도를 반복했을 가능성.
- 악기를 추가하면서 독립적인 성부 대신 선율/화음을 중복했을 가능성.
- 모티프의 반복·변형·대비와 장기 형식 계획 없이 국소 음표만 생성했을 가능성.
- 예제를 문맥으로 제시한 것을 실제 모델 훈련과 혼동했을 가능성. 별도 훈련 과정이 없다면 예시는 참고 자료이며 가중치 학습 완료가 아니다.

해결 목표는 음표 수나 화음 복잡도를 무조건 늘리는 것이 아니라 **역할, 전개, 유지와 대비, 종결, 연주 가능성**을 계획하고 검증하는 것이다.

### 10.2 기존 XML의 확인 범위와 정렬 전제

2026-10-01 읽기 전용 `rg --files MusicXML -g '*.xml' -g '*.musicxml' -g '*.mxl'` 목록에서 12,055파일을 확인했다. 이는 명령이 찾은 파일 수이며 중복 제거된 작품 수, 정렬 완료 수, 학습 적격 수 또는 검증된 편곡 쌍 수가 아니다. 전 파일을 파싱·화성 분석하거나 학습한 것은 아니다.

표본 *A Whole New World*는 XML을 실제로 읽어 아래 part와 첫 part의 기보 마디 수를 확인했다. 경로는 모두 `K:/Music Analysis/MusicXML` 아래다.

| 파일 | 확인된 part name | 첫 part의 기보 마디 수 |
|---|---|---:|
| `A Whole New World.xml` | `P1`, 이름 없는 part | 79 |
| `3. A Whole New World, Piano Solo.musicxml.xml` | Pno. | 79 |
| `3. A Whole New World, Violin and Piano Duet.musicxml.xml` | Vln., Pno. | 79 |
| `3. A Whole New World, Violin, Cello and Piano Trio.musicxml.xml` | Vln., Vc., Pno. | 79 |

| `A Whole New World, Piano Solo.xml` | Piano | 71 |

같은 제목/79마디라는 사실만으로 실제 선율과 반복 occurrence가 정렬됐다고 선언하지 않는다. 제목은 후보 묶음이며 선율·리듬·이조·삽입/삭제·반복/구절 대응과 판본을 검증해야 한다. 71마디인 다른 판본도 원본 그대로 보존한다. 위 표본은 일반 정렬/추출 계약을 검사하기 위한 출발 자료이지 특정 작품용 작곡 규칙이나 gold label이 아니다.

### 10.3 악보 형식이 아닌 변환 사례를 추출한다

**2026-10-04 task별 target 정정:** Melody 화음 파트와 각 편곡본의 실제 음표·음가·타이·배치는 **해당 편곡을 재현하는 조건부 학습의 기보 target 정답**으로 보존한다. 이는 기능화성 분석의 Roman/key/function gold와 다르며, 분석에서는 그 화음 파트로부터 만든 추정이 weak/silver 자료다. 동일 선율에 가능한 다른 편곡을 오류로 만들거나 자동 추정한 역할/스타일 의도를 사람 정답으로 승격하지 않는다. Target 정렬·원판본/사용 권한·작품 가족 split을 확인하고 기존 학습 eligibility를 자동 변경하지 않는다. [첫 측정 기록 §7](records/2026-10-04-candidate-recall-and-first-selection.md#7-편곡-target과-분석-gold의-구별).

기준 악보와 각 편곡본의 정렬된 구간에 대해 다음을 저장한다.

- **선율:** 어느 악기/성부로 이동했는지, 유지·이조·리듬 분할·연장·장식·변형된 음표의 대응.
- **베이스:** 근음 반복, 전위, 순차 진행, 페달 등의 해석 후보와 실제 음표·음가·화성 가정.
- **내성/대선율:** 화음 채움, doubling, 독립 진행, 응답의 후보 및 구간별 역할 전환.
- **반주:** 리듬, 동시/순차 제시, 음역, 보이싱, 박자 상대 슬롯, 시작/유지/종결 변형.
- **배치:** 악기가 쉬고 들어오는 시점, 선율 교대, 중첩·대비, 밀도/음역의 구절별 변화.
- **전개:** 반복 등장 사이의 공통 core와 변경된 complete extent, 추가/삭제/연장/분절 및 종결 목표.

각 레코드는 원 XML/IR revision/hash, 원 note/sounding/span refs, 앞뒤 문맥, 대응의 미정/대안, 자동 관찰과 해석 상태, 사용 권한·split을 유지한다. 서로 다른 편곡본의 note IDs를 합치지 않는다. 편곡본을 보고 사후 작성한 설명은 실제 사용자 요청과 구별한다.

다른 곡에 적용할 반주 패턴은 실제 pitch 목록만 저장하지 않는다. **박자 안의 공격 위치 + rational 음가 + 화음 상대 근음/3음/5음/7음 슬롯 + 음역 + 보이싱/성부 연결 + 시작·종결 변형 + 적용 조건**으로 표현한다. 경과음·보조음·계류·페달은 구성음 슬롯과 구별하고 화음 변경을 가로지르는 tie/sustain도 명시한다. 이런 상대 슬롯을 새 조·화음에 맞춰 실현하되 3화음용 패턴을 모든 화음 종류에 무조건 적용하지 않는다.

기존 편곡본 자체가 단조롭다면 그 자료만으로 다양성을 확보하기 어렵다. 기존 다편성 쌍은 편성 변환의 출발 자료로 쓰고, 보유한 우수한 피아노·실내악 악보에서 질감·역할 교대·전개 사례도 추가한다. 자료량만 늘리는 것과 역할/전개를 실제로 학습·검색·생성에 사용하는 것은 별개다.

### 10.4 공통 작품 계획과 네 편성의 별도 실현

공통 계획은 선율/보존 범위, 경쟁 또는 승인 화성, 화성 리듬, 프레이즈/모티프 전개, 종결 목표, 구절별 역할·질감·밀도·음역을 갖는다. 편성별 실현기는 그 계획에서 서로 다른 음표와 기보를 만든다.

| 편성 | 실현 후보의 예 | 피해야 할 고정 방식 |
|---|---|---|
| 피아노 솔로 | 선율·베이스·내성·반주를 두 손에 배치 | 같은 왼손 패턴의 무제한 반복, 선율 가림 |
| 피아노+바이올린 | 두 악기의 선율 교대, 응답, 반주 분담 | 바이올린의 선율과 피아노의 단순 doubling만 유지 |
| 피아노+바이올린+첼로 | 첼로의 베이스/대선율 역할 전환, 피아노 중복 조절 | 첼로를 항상 베이스에 고정 |
| 피아노+바이올린+비올라+첼로 | 비올라의 내성/응답, 역할 분담, 음역/밀도 조절 | 모든 악기가 계속 화음 구성음을 중복 |

네 번째 편성은 **피아노 사중주**이지 현악 사중주가 아니다. 위 역할은 계획 후보이며 모든 작품의 고정 배치 규칙이 아니다. 구절마다 누가 주도하는지와 어디서 대비를 만드는지 결정한다. 같은 질감을 의도적으로 유지할 수도 있으며 다양성을 위해 무작위로 반주를 바꾸거나 모든 악기를 계속 연주하게 하지 않는다.

### 10.5 모티프/프레이즈 하나에서 완성된 작품으로

이는 기존 선율 편곡에 **작곡·전개 기능**을 추가하는 별도 목표다.

```text
모티프/프레이즈
→ 특징·보존 범위와 변형 허용 조건
→ 형식·반복·변형·종결 계획
→ 선율·화성의 공동 생성
→ 편성별 성부·반주 실현
→ 독립 검증·악보·청취·검토
```

원형은 core/complete extent와 리듬·음정·contour의 여러 증거로 표현한다. 변형 연산은 반복, 이조, 끝부분 변화, 리듬 변화, 분절, 연장/축약, 음역 이동, 응답 등이며 어떤 음표/특징을 유지하고 변경했는지 대응을 저장한다. 모든 변형을 exact pitch 일치로 제한하거나 전혀 다른 선율을 같은 Motif라고 설명하지 않는다. 종결/대비는 화성 리듬·조성·종지 목표와 공동 조정한다.

2마디 모티프를 16마디로 전개하는 첫 시험의 한 예는 다음과 같다.

1. 첫 구절: 모티프 제시와 응답.
2. 다음 구절: 리듬이나 끝부분을 바꾼 반복.
3. 중간 구절: 일부를 분절·연장하거나 다른 음역에서 전개.
4. 마지막 구절: 원형을 회상하면서 종결.

이 예는 모든 음악에 적용할 4마디 공식이 아니다. 한 모티프는 완성곡을 유일하게 결정하지 않으므로 길이·형식·스타일·난이도·원형 보존·변형 허용 범위를 입력/계획에 둔다. 미지정 항목은 추정임을 밝힌 복수 계획으로 제안한다. 작곡 결과의 Canonical Core와 생성 의도·원형 대응·실현 연산 계보는 별도다.

### 10.6 추천 개발 순서와 첫 실증

1. **다편성 악보 대응:** 같은 작품의 실제 선율/구간을 정렬하고 유지·추가·삭제·변형·역할 이동을 기록한다.
2. **패턴 라이브러리:** 실제 원음과 앞뒤 문맥을 보존하면서 반주·성부·전개의 다른 조/화음 적용 조건을 구조화한다.
3. **짧은 피아노 편곡 실증:** 같은8–16마디 입력에 서로 다른 편곡3안을 생성하는 기능을 개발하고 이전 결과와 악보/청취 비교한다. 이 길이는 검증 단위이며 최종 전곡 목표의 축소가 아니다.
4. **다른 편성 실현:** 같은 계획을 이중주·삼중주·피아노 사중주로 실현하고 역할 교대·독립 성부·연주 가능성을 검증한다.
5. **모티프 작곡:** 하나의 모티프에서 전개·종결을 갖춘 짧은 완성 작품을 만들고 전곡으로 확대한다.

현재의 화성 분석 검증 순서를 폐기하거나 사용자 질문 때문에 즉시 생성기 구현으로 전환하는 결정은 아니다. 패턴/계획 계약과 데이터 준비는 병행할 수 있다. 화성 분석이 완벽해질 때까지 모든 생성 연구를 대기할 필요도 없다. 초기 생성 실증은 **검토된 원주석 또는 사용자가 승인한 화성 계획**을 조건으로 시작하고 `annotation-assisted`/계획 조건부 실행을 blind 분석 평가와 구별한다. 불확실한 자동 분석은 공개된 후보 A/B로 실현하고 확정 원화성을 보존했다고 주장하지 않는다.

### 10.7 평가·피드백과 AI의 역할

필수 평가는 선율/리듬 보존과 요청 준수, 주제의 일관성·변형, 구절별 반주의 적절한 유지·대비, 성부 독립/중복, 역할 교대, 음역/손폭/도약/속도·현악기 기법 등 연주 제약, 화성/불협화 준비·해결, 종결 의도, XML 출력→재파싱의 onset/음가/철자/tie/part/staff/voice 보존이다. 어려운 실제 연주성과 음악성은 자동 수치만으로 확정하지 않고 악보·청취·사람 검토로 보완한다.

계획과 출력 검증을 분리하고 생성기의 자기 점수만으로 성공을 선언하지 않는다. 여러 후보를 제시하며 요청/검증 실패 구간만 제한적으로 수정한다. 수정 횟수·사유·범위와 이전 score revision을 보존하고 실패하면 초안과 위반 보고서를 반환한다. 동일 작품의 다른 편곡본을 독립 holdout으로 취급하지 않는다.

규칙/결정론적 코드는 시간·참조·보존·hard constraints와 재현을 맡는다. 검색은 출처/적용 조건을 가진 패턴과 반례를 제공한다. 통계/AI는 역할·패턴 후보와 자연어 요구의 구조화, 복수 전개 계획·세부 후보에 선택적으로 사용한다. 모델이 만든 설명을 원작자의 의도/정답으로 저장하지 않는다. 모델 버전·계획·검색 사례·실현·검증·사람 피드백을 분리해 누적하며 저장만으로 학습 완료를 선언하지 않는다. 사용 허가·정책 확인 없이 로컬 XML/책/코퍼스를 외부 API에 전송하지 않는다.

### 10.8 참고 연구와 구현 완료 오해 방지

반주 구절을 검색·구조적으로 조합한 뒤 새 화성에 맞춰 변환하는 접근은 [AccoMontage, ISMIR 2021](https://arxiv.org/abs/2108.11213)의 참고 방향이다. 해당 연구는 folk/pop lead sheet의 피아노 반주에 초점을 맞추며 우리 실내악 편곡이나 다양한 스타일의 성능을 입증하지 않는다.

모티프→프레이즈→섹션의 반복/변형을 expert system으로 계획하고 neural model로 세부를 다듬는 접근은 [MeloForm, 2022](https://arxiv.org/abs/2208.14345)를 참고한다. 음악 형식 제어 연구의 결과를 우리 시스템의 완성곡 음악성/연주성 보장으로 사용하지 않는다. 두 링크는 직전 설명 때 원 논문 abstract를 확인한 참고 근거이며 코드를 도입하거나 모델/데이터를 다운로드·학습한 것은 아니다.

이번 추가는 사용자 응답 내용의 개발 기획 보존이다. 생성 코드·모델 훈련·편곡 실행·새 UI·원 XML/IR·기존 화성 계산/산출물은 변경하지 않았으며 Git commit/push는 하지 않았다. 이후 착수/실패/검증/승격은 [화성 개발 로그](DEVELOPMENT_LOG.md)에 별도 항목으로 남긴다.

# 여러 화음 진행의 관찰 근거 비교

HARM-DEV-20260930-10 · 2026-09-30 · `progression-evidence-0.1.0`

## 목표와 일반 규칙

직전의 다중 구간 계산기에 실제 관찰 근거를 연결한다. 사용자 승인에 따라 진행하며 작품/마디별 특별 규칙은 없다. [상세 규칙](../HARMONY_REASONING_RULES.md)의 R02/R06/R11 중 관찰 부분이며 기능·최적 경로 선택 전체 구현은 아니다.

- 같은 문맥·성부 연결·평가 범위에서 비교한다. 외부 문맥의 NCT 설명을 유지하되 외부 음가를 평가량에 더하지 않는다.
- 구성음만/혼합/비구성음만/미정/쉼의 실제 시간과 후보별 조건부 NCT 설명을 별도 기록한다.
- 실제 최저 MIDI 음을 구하고 동음 중복 refs도 보존한다. 음높이 하나라도 미확인이면 최저음을 추정하지 않는다. silence는 음높이가 바뀌었다는 뜻이 아니다.
- 구간 안 누적 구성음이 완성되는 시각, 비구성음 동반, 후보 누락/보류를 기록한다. 누적 집합 완성만으로 분산화음을 확정하지 않는다.
- 경계 양쪽 후보의 구별 구성음, 지속음의 역할 변화, 실제 최저음 변화를 기록한다. 구성음 집합이 같아도 전위/기능이 다를 수 있으며 구별음도 다른 해석에서는 장식음일 수 있다.
- 비교 결과는 구성음/NCT 등의 음가 차이와 경계 수 차이를 분리한다. 더 많이 쪼개어 구성음 설명량이 늘어났다고 자동 채택하지 않는다. 공통 음표에서 나온 상관된 근거를 독립 확률로 합산하지 않는다.

## 구현 파일 및 계약

- `src/musicanote_harness/harmony_progression_evidence.py`: `lowest`, `vector`, `compare`.
- `src/musicanote_harness/harmony_progression_evidence_trial.py`: 고정 경로 재실행 및 hash/제외 기록.
- `tests/test_harmony_progression_evidence.py`:10개 반례/보존 테스트.

벡터는 정확한 span·event refs·candidate ref/alternative·path 선택 위치·성부 연결 ID를 보존한다. 전위는 현재 compact 후보의 근음과 구조적 베이스 역할 계약이 없어 명시적으로 보류한다. 표시 라벨을 문자열 파싱해 근음을 몰래 추측하지 않는다. 이는 기존 전체 후보 공급기에 근음 정보가 전혀 없다는 주장이 아니라 이번 compact 경로 인터페이스의 한계다.

## 핵심 반례

C–D–E를 C화음 문맥에서 설명하면 D는 조건부 경과음이다. 각 음을 C/G/C 구성음으로 설명하는3구간 경로는 구성음 설명량이1quarter 늘어난다. 테스트는 그 증가와 경계2개 증가를 동시에 보존하고 `preferred=null`을 요구한다. 이 경로는 기술적 반례이지 음악적 정답이 아니다.

추가 검사: 동일 구성음 경계 삽입에도 셀 관찰 불변, 최저음 변화만으로 화음 교체 확정 금지, 쉼 처리, 구성음 완성만으로 분산화음 확정 금지, 후보 blocker 보존, 부분 평가의 외부 문맥, 동음 최저음 refs, 미확인 pitch, 입력 불변.

## 실제 표본 실행

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m musicanote_harness.harmony_progression_evidence_trial --source output/harmony-progression-context-2026-09-30-r3 --output output/harmony-progression-evidence-2026-09-30-r1
.venv/Scripts/python.exe -m unittest discover -s tests -q
```

출력 폴더는 재사용하지 않는다. `run-contract.json`에 코드/source report hash, 표본별 JSON에 원입력 hash와 실험, `report.json`에 모든 표본 상태를 남겼다. 기존 표본 선택/가설을 변경하지 않고 이전 기술 probe와 동일 구성음 검사만 재사용했다. 원주석은 읽지 않았다. 원악보/IR은 이전 단계의 case-provenance/source-snapshot과 입력 hash 체인으로 추적한다.

## 남은 작업과 적용 범위

우선 근음/화음 도수와 베이스 역할의 구조화된 계약을 compact 후보에 연결하고, 구성음 베이스/비화성 베이스/페달을 경쟁 가설로 검증한다. 이후 기능·해결·조성 근거와 후보 누락을 확인한 뒤 경로 순위를 도입한다. 이 관찰 결과만으로 점수 가중치를 임의 지정하지 않는다.

운영5173/구조 분석/Core/원주석과 악보 화면은 변경하지 않았다. 새 브라우저 검토 페이지가 아니며 기존8822화면에 이번 계산은 표시되지 않는다. 외부 AI 호출이나 GitHub 업로드는 없다.

# 화음 경계의 실제 동시음·최저음·박절·구성음 시간 지지

기록 ID: HARM-DEV-20260930-03. 관찰 증거 추가 단계. 후보 자동 탈락/최종 화성 선택/운영 승격은 수행하지 않았다.

## 배경과 목표

[직전 지속음 경계 검사](2026-09-30-held-boundary-coverage.md)에서 하행 계류 형태가 나와도 그때의 실제 화음 근거가 부족할 수 있음을 확인했다. K281 sample16의 B♭→A에 대해 임의의 E♭major→Dmajor 조합이 계류 후보를 만들지만, 실제 Dmajor나 계류음이라는 결론은 내릴 수 없었다.

이번에는 같은117경계·184표본을 유지하며 다음을 **별도 관찰 증거**로 붙인다. 새 작품/마디 예외, 원주석 역주입, 화음 후보 생성 변경, 강제 정답 또는 학습은 없다. 새로운 교재 단원 독해가 아니라 이미 구분한 관찰/해석 계약의 구현이다.

## 일반 계약

### 1. 정확한 시간 셀과 최저음

- 기존 attack/release/가정 경계의 유리수 시간 셀 `[start,end)`를 사용한다. 셀에 실제 지속하는 전 part sounding event IDs를 보존한다.
- 경계에서 끝난 음은 경계 뒤 셀에 포함하지 않는다. 경계에서 시작한 음은 포함한다. 새 attack과 이미 지속 중인 음은 따로 기록한다.
- 최저 MIDI pitch의 모든 event를 보존한다. 동음 중복 성부에서 임의 하나를 선택하지 않는다.
- 철자/옥타브/MIDI 검증이 실패한 active pitch가 있으면 그것을 제거하고 다른 음을 최저음으로 올리지 않는다. 최저음 판단을 보류한다.
- 최저음 없음(쉼)과 음높이 미정은 구별한다. 최저 음높이 변화와 같은 음의 재타격도 구별한다.
- 이 값은 **실제 최저음**이며 structural bass, root, inversion이 아니다. 실제 베이스가 비화성음일 수 있다는 가능성도 남긴다.

### 2. 수직 음정과 음형의 시점 연결

- 각 셀에서 최저음과 모든 active event 사이의 철자상 도수 및 반음 수를 저장한다. 예를 들어 C–F와 C–E♯를 같은5반음이라는 이유로 같은 도수로 만들지 않는다.
- 복합 음정은 복합 도수로 유지한다. 협화/불협화 판정과 장·단/증·감 명칭을 새로 확정하지 않는다.
- 기존 pattern ID와 affected event, 비구성음 적용 셀 목록, 근거 음들의 onset 셀을 연결한다. 준비·가정 경계·해결음의 실제 베이스가 달라지는지 추적할 수 있다.
- 동일 lowest pitch의 여러 event도 각각의 관계 ID를 남긴다. 음정 개수를 독립적인 찬성표로 합산하지 않는다.

### 3. 박절 위치

- 셀 시작을 포함하는 IR measure를 정확하게 찾는다. 마디선에서는 다음 마디의 박자표가 적용된다.
- printed measure number, 마디 내 quarter offset, 표기 박자, **박자표 분모 음가 단위로 경과한 위치(0-based)**를 저장한다. 셋잇단음표는 유리수 그대로다.
- 6/8의 분모 단위3을 자동으로 '세 번째 박'이라 부르지 않는다. 복합·가산박 그룹/강약/하이퍼미터는 추론하지 않는다.
- 못갖춘마디 및 명목 길이와 다른 마디는 단순히 마디 시작이라는 이유로 downbeat를 확정하지 않는다. 실제/명목 길이가 같은 일반 마디의 시작 여부만 분리 기록한다.
- 마디 누락/겹침, 분모 부재는 명시적으로 보류한다. 박자표의 마디 내부 변경과 성부별 polymeter는 이 IR measure 표현이 제공하지 않는 한 복원하지 않는다.

### 4. 구간별 구성음 지지

- 각 후보의 **철자 구성음별 관측 시간 합집합**을 구한다. 같은 C가 두 옥타브/두 성부에서 동시에 울려도 C의 지속 시간을 두 번 더하지 않는다.
- 구성음별 지지와 모든 구성음의 동시 출현 시간을 분리한다. 분산화음은 모든 구성음이 동시에 안 나와도 가능하므로 동시 출현0을 탈락 기준으로 사용하지 않는다.
- 각 셀의 관측/미관측 구성음도 저장한다. 알 수 없는 pitch가 포함된 셀은 미관측을 확정적인 부재로 표현하지 않는다.
- 이 합집합 시간은 종전 **전체 note-time**과 다른 척도다. 원래 note-time 비교/분류 수치는 변경하지 않는다.
- 같은 범위·구성음 집합의 지지는 중복 저장하지 않고 profile ID로 연결한다. 모든 hold/left/right reading 색인과 profile 참조를 유지한다. 기존 후보 보류 조건은 그대로이며 새 지지량이 보류를 해제하지 않는다.

## 실제 사례: 후보의 약점을 보이는 관찰

K281 III `reviewm_555ff701230fc0b8ee66`, sample16, 경계 global21/2:

| 항목 | 실제 관찰 |
|---|---|
| 직전 `[10,21/2)` | E♭4·B♭4·A5, 최저음 E♭4 |
| 직후 `[21/2,11)` | E♭4·B♭4·G5, 최저음 E♭4 유지, 새 attack G5 |
| 박절 | printed3마디 +1/2quarter, 표기2/2의 분모 음가(2분음표)로1/4 경과 |
| B♭4 대 최저음 | 경계 직후 E♭4 기준5도/7반음 |
| A4 onset | 그 시점 최저음 C4 기준6도/9반음 |
| Dmajor 뒤 후보 | 직후 A·D·F♯ 모두 미관측. 전체 뒤 범위에서 A1quarter, D1quarter, F♯0 |
| E♭major 뒤 대안 | 직후 E♭·G·B♭ 모두 관측. 전체 뒤 범위의 전 구성음 동시 출현1/2quarter |

따라서 하행 형태만으로 계류음과 Dmajor를 확정할 근거가 없음을 구체적으로 확인할 수 있다. 실제 최저음과의5도/7반음 관계, 경계 시점 Dmajor 구성음0을 함께 보아야 한다. **이 사례의 전체 뒤 범위를 E♭major로 확정한 것도 아니다.** 이후 C4/A4 등이 나타나므로 여러 화성 변화 가능성과 적정 구간 길이는 별도 문제다.

기본 화면의 Cmajor 유지, E♭major→Dmajor는 이전 단계에서 고른 검사 예시이지 추천이 아니다. E♭major로 뒤 후보를 바꾸면 즉시 관측 구성음3개가 나타나며 계류 후보는 사라진다. 화면 검증 후 원래 예시로 복원했다.

[전체 악보 사례](http://127.0.0.1:8820/real-cases/reviewm_555ff701230fc0b8ee66/whole-score.html?sample=16) · [목록](http://127.0.0.1:8820/index.html). 서버 실행 중에만 열린다. 오른쪽 ‘실제로 울리는 음과 최저음’에서 근거를 확인할 수 있다. 기존 악보 구간/경계/역할 차이 표시는 유지한다. 일반 pitch·root/quality는 Campania로 바꾸지 않는다.

## 구현과 검사

- `harmony_boundary_observations.py`: `meter_at`, `snapshot`, `support`, `observe`, `augment`.
- `harmony_boundary_observations_trial.py`: 같은 자료 전체에 증거만 추가하고 원래 필드/원본 불변 검사. score snapshot과 전체 악장 화면 재사용.
- `visual_review_assets/segment_contrast.js`: 실제 경계 동시음·최저음·분모 위치, 선택된 후보의 셀/시간 지지, 활성 음형의 수직 음정 표시. 새 필드 없는 이전 자료도 계속 지원한다.
- 신규22테스트: release/attack, 동음 베이스 유지, 최저음 중복, 이명동음 도수, 미정 pitch/쉼, 분산화음, 중복 시간 방지, 유리수·복합박·못갖춘마디·마디선 박자 변경, 누락/겹친 마디, 주석 비의존, 보류/원자료 불변, 잘못된 셀 분할, pattern 시점 refs, 리듬 비례 축소.
- 첫 테스트에서는 기존 경량 fixture에 measure ID가 없어 실패했다. 실제 Canonical measure 계약의 ID/printed number/nominal duration을 fixture에 채웠다. 검사를 제거하거나 실제 자료를 바꾸지 않았다.
- 전체 Python 테스트 **1,549개 통과**. Verovio encoded-break 경고1건, 실패 없음.
- r1 뒤 셀 분할의 gap/overlap 검증을 강화하고4개 테스트를 추가해r2로 재실행했다. 실행별 코드/UI hash는 run-contract에 기록한다. r1/r2 중간 출력은 삭제하지 않는다.
- 브라우저에서 새 수치와 Python 출력을 대조했다. 뒤 후보 Dmajor↔E♭major 전환 시 지지 목록/NCT 표시 갱신과 전체 악보 범위 표시를 확인했다. 사용자 음악적 검수 완료를 뜻하지 않는다.

## 결정과 다음

관찰 증거 계약과 화면 비교를 채택한다. 계류/선행음 확정 규칙 및 후보 탈락/순위 결정은 이번 변경에 없다. 특히 '최저음이 유지되면 화음도 유지', '동시3음이 없으면 화음이 아님', '분모 격자 밖이면 계류가 아님' 같은 단정 규칙을 만들지 않는다.

다음은 관측된 음정/박절/시간 지지를 이론상의 준비·불협화·해결 조건에 연결하고, 분산화음의 늦은 구성음과 경계가 잘못 놓인 후보를 구별하는 **보류 사유와 경쟁 가설**을 설계하는 단계다. 실제 화성/성부 정답 사례와 반례를 대조한 뒤에만 자동 판단 승격을 검토한다.

# 단계94 — 원악보의 후속 문맥을 공동 화음 선택에 연결

## 목적과 적용 범위

단계93에서 확인한 짧은 탐색 범위 끝의 기능적 6/4 근음 오류를 먼저 보완한다. 원악보가 끝난 것이 아니라 평가 구간만 끝난 경우, 기존 선택기는 다음 **선택된** 화음을 요구해 전체 원음표가 있어도 해결 근거를 못 쓰는 일이 있었다.

새 근거는 원악보의 실제 다음 음표를 읽는다. 다음 주석 화음이나 정답 조성은 읽지 않으며, 종지적 6/4 또는 다음 화음을 확정하지 않는다. 같은 구성음/다른 근음 오류는 이전 완료 오답 시간의 약20.72%였으므로 영향이 있는 문제지만, 가장 큰62.5%의 근음·구성음 동시 오류를 전부 해결하는 작업은 아니다.

## 일반 규칙

- 끝이 실제 탐색 범위 끝인 기능적 6/4 후보에만 새 후속 문맥 특징을 계산한다. 내부 경계는 기존의 실제 선택 화음 쌍 근거를 유지하며 중복 보너스를 붙이지 않는다.
- 원악보의 **다음 기준박2개**를 유리수로 읽는다. 변박과 복합박자를 환산하며 unknown 박자를 추정하지 않는다. 2박은 현재의 제한된 설계 가설이지 모든 음악의 해결 길이를 확정한 이론 규칙이 아니다.
- 원후보의 표면 3화음 구성음이 앞 구간의 union으로 관찰되고, 기능적 근음이 앞뒤에서 최저음으로 관찰되며, 그 근음의 장3화음 구성음이 후속 union으로 관찰되는지를 따로 저장한다. 동시에 전부 울릴 필요는 없다. 분산화음 제시가 가능하지만 후속 union을 확정된 화음으로 내보내지 않는다.
- 명시 part/voice의 유일하고 끊기지 않은 원음표 연결에서 4→3, 6→5 하행이 있으면 별도 추가 증거를 만든다. 다성 기보에서 상성부를 추측하여 연결하지 않는다. 둘 중 하나만 있으면 비례 점수이고, 둘이 없더라도 표면/베이스/후속 구성음 관찰과 구별한다.
- 다음 음표들이 그 장3화음을 지지하지 않으면 known zero다. 원자료가 문맥 길이를 덮지 못하거나 음높이·성부·시간·박자가 불확실하면 null이다. unknown을 다음 화음 부재로 바꾸지 않는다.
- 앞서 만든 7음 소멸 tail은 별도의 양수 비용으로 같이 시험한다. 원기보/tie와 실제 sounding release를 유지하며, 7음 생략을 금지하거나 원음을 삭제하지 않는다.

## 선택기와 학습 계약

원35항 계수, 후보망, 원 ID, raw 구간 상한, exact Fraction DP와20초/2M guard는 고정한다. 새3항의 run 비용만 private dependency로 연결한다. 같은 signature의 raw 분할은 union run으로 계산하므로 비용이 늘어나지 않는다. 원35항의 독립 winner reconstruction 검사도 유지한다.

새 계수는 Train 자료에서만 정한다. 기존 활성240대조와 봉인한 Train 완료 오답 중 아직 대조에 없는 경로를 포함한다. 새3항의 절댓값을 `0, 1/4, 1/2, 1, 2`로 제한한125개 조합에서 작품군 균등 hinge와 작은L1 비용을 비교한다. 원35의 양수 경쟁 margin은 원값의 절반 이상을 유지해야 한다. 연속 전역 최적점이나 확률 보정 모델이 아니다.

특징이 두 전체 경로에서 모두 알려진 차원만 학습 목표에 들어간다. 실제 선택의 알려진 부분 비용은 별도로 보존하며, 보호 margin에서는 그 실제 부분 비용도 확인한다. 기능적 형태의 소멸 특징이 unknown이라는 이유로 다른 알려진 후속 문맥 차원까지 버리지 않는다.

모델을 먼저 봉인하고118 Train 원구간을 전부 새 선택한다. 모든 예측을 먼저 봉인한 뒤 주석을 대조한다. 시간 보류를 제외한 정확도를 전체 성능으로 쓰지 않으며, 계산 보류를 과거 승자로 채우지 않는다. Dev 재학습·운영/UI·Claude 연결·Git 업로드는 이번 범위 밖이다.

## 결정과 다음 우선순위

이번 특징은 실제 선택까지 연결해 시험했지만, 정해진 학습 목적에서 새 계수가 모두0이고 결과도 같다. 따라서 운영/UI/편곡 시스템에 연결하거나 같은 모델의 Dev 재실행을 추가하지 않는다.

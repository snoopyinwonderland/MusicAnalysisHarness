# 분산 구성음과 지연 해결의 보수적 시간 경로 검사

HARM-DEV-20260930-17 · 2026-09-30 · `distributed-resolution-0.1.0`

## 목적과 적용 범위

사용자가 승인한 다음 단계: 경계에서 구성음이 동시에 울리는 조건만으로 놓치는 분산형·지연 도착을 검사한다. 기존 직접 해결 결과는 그대로 두고 **별도의 가능성 근거**를 추가했다. 특정 작품/마디/정답 라벨을 조건으로 쓰지 않는다.

이론적 출발점은 분산된 구성음, 이끎음의 반음 상행, 7음의 순차 하행, 지속/동음 재타격 이후의 지연 도착이다. 다만 아래 조건들은 이론 전체의 필수 조건이 아니라 **이번 실험의 좁은 충분 근거 계약**이다. 음이 생략된 화음, 쉼이 있는 분산 반주, 복합 비화성음도 음악적으로 가능하며 미지원은 오답 판정이 아니다.

## 일반 규칙

1. 원 IR의 음표·sound ID/철자/시간/part/voice 및 전체 문맥 event coverage를 기존 검사기로 검증한다. 원자료/기존 assignment/직접 판정은 수정하지 않는다.
2. 기존 후보의 서로 닿는 두 구간에서 각각 철자로 된 **모든 후보 구성음이 시간에 걸쳐 관측되는지** 기록한다. 동시성은 강제하지 않는다. 관측되지 않은 근음·3음·5음·7음을 생성하지 않는다. 생략 허용은 후속 단계다.
3. 단순 넓은 창의 pitch 합집합을 증명으로 삼지 않는다. 출발 구간의 비구성음은 독립 NCT 설명이 필요하므로 현재 보류한다. 전체 성부가 쉬는 셀도 기록하고 보류한다.
4. 이끎음/7음은 출발 구간에서 실제 관측된 sound에서 시작한다. 같은 part/voice의 시간상 닿는 연결만 사용하며, 동일 철자·옥타브의 재타격은 이어갈 수 있다. held sound는 원래 duration 그대로 유지한다.
5. 목표 구간 안에서 실제 음높이·철자의 적절한 순차 해결에 도착해야 한다. 이끎음은 목표 근음으로 반음 상행, 7음은 목표 구성음으로 온음/반음 하행이다. 다른 음이나 쉼을 건너뛰지 않는다.
6. 두 해결 경로가 **함께** 존재할 수 있어야 한다. source가 두 음으로 분기하거나 두 source가 하나의 target으로 병합되는 가설은 거부한다. 그 외 sound도 고립 track으로 보존한다.
7. 목표의 비구성음은 선택된 경로에서 앞 화음으로부터 실제 지속/재타격되는 이끎음·7음이어야 한다. 같은 pitch라도 중간에 새로 들어온 다른 성부의 음까지 설명했다고 하지 않는다.
8. 만족하면 `temporal_resolution_possible`: 한 대응 아래 가능한 시간 근거다. Secondary/조성/종지/실제 성부/최적 화음/경계 정답의 확정이 아니다. subset 화음의 중간 변화까지 배제한 것이 아니다.
9. 경로 탐색과 공동 대응은 각각 4,096회 기본 한도를 둔다. 초과하면 보류이며 부분 검색의 실패를 부정 증명으로 쓰지 않는다. 전체 후보 pair 예산은 이전과 같이 표본 단위 보류한다.

## 코드와 회귀

- `src/musicanote_harness/harmony_distributed_resolution.py`: 시간별 구성음 출처, 누락/비구성음/쉼, 동음 chain, 해결 path, 공동 witness 및 보류.
- `harmony_candidate_relation_survey.py`: v0.2.0, 선택적 `temporal=True`; 기존 직접 `query`와 새 `temporal_query`를 별도 보존.
- `harmony_candidate_relation_trial.py`: `--temporal`; 계획·원자료 hash·권한 검사와 별도 요약 유지.
- `tests/test_harmony_distributed_resolution.py`: 신규 18개. 조옮김, 미관측 구성음 보존, 공동 탐색 예산, 0음가 미지원 보존을 포함한다. 최종 전체 Python 1,730개 통과(24.5초). 기존 layout warning은 있었으나 실패는 없었다.

양성: 시간차 구성음, 늦은 근음/3음, 지속음·동음 재타격 후 해결. 반례: 출발 비구성음, 중간에 새로 나타난 목표 비구성음, 성부의 쉼, 전체 쉼, 잘못된 옥타브 도약, 경로 병합 충돌. 보류 조건·IR 불일치 거부·입력 불변·기존 직접 판정 불변·survey 연결도 검사했다. 합성 결과를 실제 악보 정확도로 해석하지 않는다.

## 고정 실제 표본 재실행

```powershell
$env:PYTHONPATH='src'
.venv/Scripts/python.exe -m musicanote_harness.harmony_candidate_relation_trial --source output/harmony-progression-context-2026-09-30-r4 --ir-source output/harmony-shared-context-2026-09-30-r1 --output output/harmony-distributed-resolution-2026-09-30-r1 --max-pairs 1024 --temporal
.venv/Scripts/python.exe -m unittest discover -s tests -q
```

13개 고정 표본/모든 후보 관계 계획/기존 1,024 pair 한도를 유지한다. `plan.json`, `run-contract.json`, 표본별 JSON, `report.json`은 로컬 output에 저장한다. 원본 IR·source hashes·train/internal 권한은 이전 snapshot 체인으로 검증한다. 원주석을 정답 입력으로 사용하지 않는다.

실행 완료: 이전과 동일하게 10,546관계를 계획하고 1,847개를 검사했다. 8,699관계인 표본은 전체 예산 보류, 별도 1표본은 기존 baseline 보류다. 11개 처리 표본 중 7개는 해당 형태 관계가 0개였다.

총 1,722개는 시간 전제에서 보류되어 경로 탐색까지 진행하지 못했다. 이 중 구성음 미관측은 1,646개, 출발 비구성음 설명 부족은 1,542개다. 두 사유는 중복된다(1,466개). 전체 쉼으로 인한 추가 보류는 이번 표본에 없었다. **실제 시간 해결 양성은 0개이며, 정확도 0%라는 뜻은 아니다.** 합성 양성만 통과한 상태다.

세부 구성음 미관측(출발/목표): K281 sample16은 892/714, K280 sample16은 567/468, sample32는 96/112다. 완전한 후보 구성음이 양쪽에서 관측된 K280 sample16의 76개도 출발 비구성음 설명이 필요해 보류했다.

기존 직접 검사 요약은 직전 실행과 같았다: 동시음 전제 부족 1,698 / 직접 연결 부재 24 / 0음가 미지원 120 / 기존 blocker 5. 따라서 새 시간 가설이 기존 결과를 덮어쓰거나 정답을 늘린 것은 아니다.

마지막 검증에서 두 실행의 직접 요약 일치 및 모든 표본 artifact SHA-256 일치를 확인했다. `git diff --check` 오류 없음(기존 CRLF 안내만 있음). 관련 새 파일은 미추적 상태이므로 이 검사가 새 파일 전체의 형식 검증을 대신하지 않으며, 신규 모듈은 위 테스트로 실행 검증했다.

### 해석 수정과 추적 가능한 예

직전 실험의 “동시음 전제 부족”은 **시간차 때문에만** 실패한다는 뜻이 아니었다. 이번에 시간 전체로 확장해도 구성음이 관측되지 않는 후보가 다수임을 확인했다. 실제 표본에서 “분산화음을 놓치는 것이 주원인”이라고 아직 단정할 수 없다.

예: `reviewm_555ff701230fc0b8ee66`, sample16 첫 관계. 출발 `open_b6d78c6d8ea460d3807b`는 B♭–D–F 후보인데 F가 없고, 목표 `open_c9092a1ace855eea9304`는 E♭–G–B♭ 후보인데 G가 없다. 출발 B♭ refs는 `sound_35b7887b38fd`, `sound_8ff47e2a2a7a`, D ref는 `sound_d2dd7a88767d`다. 목표 E♭ ref는 `sound_d8a61153020f`, B♭ ref는 `sound_0b9d0a329fff`다. 로컬 검사 범위는 global quarter `[9,21/2)`, 부모 관찰 범위는 `[9,13)`다. 이 예는 누락을 설명하는 진단이지 확정 화성이나 독립 정답이 아니다.

재현 파일: `output/harmony-distributed-resolution-2026-09-30-r1/reviewm_555ff701230fc0b8ee66/16.json`. 원 IR은 `output/harmony-shared-context-2026-09-30-r1/real-cases/reviewm_555ff701230fc0b8ee66/source-snapshot/candidate_revision_ir.json`. 모든 후보별 구성음/비구성음 refs와 부모/로컬 범위를 보존한다.

## 결정과 후속 과제

이번 코드는 독립 실험 계층으로 유지한다. 운영5173/구조 분석/기존8822화면/원주석/Core는 변경하지 않는다. 외부 AI 호출/학습/GitHub 업로드 없음.

전체 구성음이 없거나 비화성음 설명이 없으면 지연 해결만 추가해도 실제 양성은 나오지 않을 수 있다. 후보 구성음 관측 누락, 관찰 문맥 절단, 독립 NCT 설명을 구분해 진단해야 한다. 성공 수를 만들기 위해 창을 무조건 늘리거나 모든 음을 비화성음으로 면제하지 않는다. grace timing, 생략 화음, 중간 장식 경유, subset 화음 변화, 기능/조성 및 독립 음악적 검증은 미완료다.
